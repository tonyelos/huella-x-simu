# 层级识别与残差策略

> 问题：能不能先做一层简单识别，第二层把已经识别过的内容过滤掉，再进一步识别？
> 结论：**可以，而且这是正确方向；但不能“删掉”已知源，必须做“标记 + 模型扣除/掩膜 + 残差检测”，并保留溯源。**

---

## 0. 一句话

```text
L1 高召回检测
  → L2 已知源/伪源标记与 PSF 模型扣除
  → L3 残差图低阈值检测（可多波段/多历元）
  → L4 星表/历表比对与分类
  → 未识别/不确定项明确保留
```

这不是“识别一次就删除”，而是**级联检测（cascade）+ 残差分析（residual analysis）**。

---

## 1. 两种“层级”要分开

### A. 检测层级（先亮后暗）

```text
L1：亮源/高置信源（高召回）
L2：把 L1 已知源从图中扣除/掩膜
L3：在残差图上找暗源/伴星/新候选
```

适合：

- 提高暗源检测；
- 找亮星附近的伴星；
- 减少亮源旁瓣/光晕对暗源的影响。

### B. 分类层级（先易后难）

```text
L1：快速规则（点源/延展、S/N、FLAGS）
L2：星表匹配（Gaia/2MASS/WISE）
L3：颜色/光谱/多历元分类
L4：物理参数推断（仅在数据足够时）
```

适合：

- 先排除明显伪源；
- 再对“不确定”的少量源做重分析；
- 避免对所有源都跑重模型。

两种可以组合，但不要混为一谈。

---

## 2. 推荐架构

### L1：高召回检测

- 匹配滤波/SExtractor/`sep`，阈值可略低（如 4–5σ）；
- 输出：位置、S/N、PSF、FLAGS、质量标记；
- 保留所有候选，不急着定性。

### L2：已知/伪源标记

- **已知源**：Gaia/2MASS/WISE/SIMBAD 匹配；
- **伪源**：FLAGS、边缘、饱和、ghost、streak、负像素、跨历元不重复；
- **亮源 PSF**：用 EPSF 做模型扣除，而不是简单画圆删除；
- 对高自行星：按 PM 预测到该历元的位置再扣除；
- 对变星：逐历元扣除，不能用一个平均位置。

### L3：残差检测

```text
residual = image - Σ(known_source EPSF models) - background
```

- 在 residual 上重新检测（可降低阈值）；
- 多波段/多历元重复确认；
- 输出 `residual_candidate`，标 `parent_id`/`masked_by`；
- 不把残差直接叫“新天体”。

### L4：身份/分类

- Gaia/2MASS/WISE/SIMBAD；
- 运动/变光；
- 颜色/SED；
- 太阳系历表（MOST/JPL/MPC）；
- 物理参数只在数据足够时给。

---

## 3. 为什么不能“简单过滤掉”

1. **亮星 PSF 不是圆盘**  
   硬掩膜会连暗伴星/背景一起删；应做 EPSF 模型扣除。
2. **高自行星位置会变**  
   固定像素掩膜会误删或漏删；要按 PM 预测。
3. **变星亮度会变**  
   用一个平均模型扣不干净；逐历元处理。
4. **6.15″/px 混合**  
   一个亮源 PSF 覆盖多个暗源；扣不干净会留残差，扣过头会删真源。
5. **错误传播**  
   L1 把真源误标成 known/artifact，L2 就永久丢失；必须保留 `uncertain` 和审计。
6. **选择偏差**  
   只测残差会系统性漏掉被掩膜区内的源；统计上要说明。

---

## 4. 在当前项目中的落点

### 已有

- A/C：源列表、质量标记；
- B/D：Gaia 匹配、RUWE/PM；
- C-P1A/P1B：本地/on-demand 源；
- app：源覆盖、锁定、识别卡。

### 需要新增

1. **`stage` 字段**：`L1` / `residual` / `catalog` / `uncertain`；
2. **`parent_id`/`masked_by`**：残差源来自哪个已知源；
3. **EPSF 模型扣除**：先用 33×33 PSF；饱和源用翼部/星表；
4. **高自行 PM 预测**：用 Gaia PM 预测每期位置；
5. **残差检测器**：同波段/多波段；
6. **审计表**：哪些源被 mask、为什么、是否可恢复。

### 推荐输出

```json
{
  "candidate_id": "...",
  "stage": "L1|residual|uncertain",
  "parent_id": null,
  "masked_by": ["gaia:..."],
  "reality": "real_source|artifact|uncertain",
  "identity": "known_star|ambiguous|uncatalogued_candidate",
  "motion": "S|V|L|A|U",
  "confidence": 0.8,
  "caveats": ["residual near bright star", "single epoch"]
}
```

---

## 5. 先做什么（最小可行）

1. 在 C/app 的 source 表加 `stage`/`parent_id`/`masked_by`；
2. 只对 **L1 高置信已知亮源**做 mask/PSF 扣除（不碰暗源/不确定源）；
3. 在 residual 上重跑一次检测，输出 `residual_candidate`；
4. 用 Barnard 场做对照：L1 47 源 → mask 亮星 → residual 新源；
5. 用 Gaia 真值检查：新源是真暗星、伪源还是混合；
6. 不把 residual 新源直接叫“新星”。

---

## 6. 验收标准

- L1 召回率（相对亮星 Gaia 子集）不下降；
- L2 mask 不误删已知亮源以外的真源（用注入源测试）；
- residual 新源中，Gaia 有对应/无对应比例可解释；
- 不出现“mask 后把真源永久删除”；
- 每个 residual 源有 `parent_id`/`masked_by`/`caveat`；
- 不把 `no_match` 写成“新天体”。

---

## 7. 结论

**可以分层，而且应该分层；但“过滤掉已识别内容”要理解为“标记 + PSF 模型扣除 + 残差检测”，不是删除。**

正确顺序：

```text
高召回 L1
  → 已知/伪源标记
  → EPSF 扣除
  → 残差 L2
  → 星表/历表/多波段确认
  → 不确定项保留
```

这能提高暗源/伴星发现率，但**不能保证所有剩余点都是新天体**；仍然需要星表、颜色、时间和后续观测。
