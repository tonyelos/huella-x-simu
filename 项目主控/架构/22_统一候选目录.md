# 统一候选目录计划（A/C/Tracks）

> 目标：把 A 源表、C 源表、Tracks 三层结果合并成一张可审计的候选目录，避免“同一源被算多次”，并支持 CSV/JSON 导出。

---

## 0. 数据来源

- A：`state.sources` + `state.aSourceBatch.byId`（215）
- C：`state.anyfieldSources` + `state.anyfieldBatch.byId`（111）
- Tracks：`state.tracksData.tracks`（256；可现取 `/api/tracks?analysis_id=...`）

---

## 1. 合并规则

### A/C 源行

- `origin` = `A` / `C`；
- 按 `(mjd, round(ra,6), round(dec,6))` 去重；
- 同位置 A/C 合并为一行，`origins="A;C"`；
- 身份取批量结果；若只有一边有结果，保留另一边 `status=unknown`；
- 不把不同位置强行合并。

### Track 行

- 每个 track 一行，`origin="track"`；
- 保留 `track_id/level/model/n_epochs/catalog_id`；
- 不展开节点；不把 track 节点另算 A/C 源；
- 同一 track 不重复。

### 统计

```text
rows, unique_sources, tracks, known, ambiguous, no_match, insufficient, unknown
```

---

## 2. UI

- 在 A 源表 actions 增加“统一候选目录”按钮；
- 点击：
  1. 若 `state.tracksData` 为空，按 `analysis_id` 拉 `/api/tracks`；
  2. 合并 A/C/loaded tracks；
  3. 打开 `<details>` 表格（前 80 行）；
  4. 显示 counts；
  5. 提供“导出 CSV / JSON”（复用/扩展 batch_export）。
- 表格列：
  `origin | epoch/track | RA/Dec | status/level | catalog_id | sep | caveats`。
- 明确“候选目录不是发现目录；track 行不是新源”。

---

## 3. 测试

- 纯函数：
  - A/C 同位置合并；
  - 不同位置不合并；
  - track 不展开、不重复；
  - counts 正确；
  - `unknown` 不写成 no_match。
- UI 静态：按钮、表格、导出；
- 现有 282 tests 不回归。

---

## 4. 验收

- Barnard：A 215 + C 111 + Tracks 256：
  - unique source 行按位置去重；
  - track 行 256 或 UI 显示上限；
  - counts 与来源一致；
  - CSV/JSON 导出；
  - 无 JS error；
- T1/T6。

---

## 5. 风险

| 风险 | 缓解 |
|---|---|
| A/C 同位置但不同源 | 只在同 mjd + 0.1″ 内合并，保留 origins |
| Track 重复节点 | 一 track 一行 |
| Tracks 未加载 | 按 analysis_id 现取 |
| 状态冲突 | 保留两边状态，标 conflict |
| 大表卡顿 | 显示前 80 行，计数全量 |
