> 目标：不再分析外部数据包；以 NASA 官方 5 个实例为**只读基准**，优化我们的识别机制。
> 边界：官方实例不能被直接写成“已标记/已确认”；它们只用于对照、回归和阈值校准。View → MoveScope 跳转保留。

## 2. 优化机制：星表先验 motion

### 问题

Barnard 的 SPHEREx 4 期基线只有 204 天，位移 5.3±6.7″，μ 显著性 1.24；当前直接判 `S`，UI 显示“静止”。
但它有 Gaia PM=10.36″/yr，测量值与 Gaia 在 1σ 内一致；`S` 是错误叙事。

### 规则（通用，不针对 Barnard 写死）

在 `build_identification` 之后增加后处理：

```text
若 result.class == "S"
且 identification 有单候选/ambiguous 的 Gaia PM
且 |μ_measured - μ_catalog| <= 3σ
且 μ_catalog > 1000 mas/yr：
  class = "L"
  basis = "catalog_prior"
  quality += ["CATALOG_PRIOR_MOTION", "MEASUREMENT_NOT_SIGNIFICANT"]
  confidence <= 0.6
  public_text: 明确 SPHEREx 未独立测出，采用 Gaia 先验
```

若：

- 没有 Gaia PM；
- 或星表 PM 与测量不相容；
- 或 PM 本身不显著；

则保持原 `S/U`，不强行改成 L。

### 输出字段

```json
"catalog_motion": {
  "pm_mas_yr": 10362.4,
  "pm_err_mas_yr": 0.036,
  "basis": "catalog_prior",
  "consistent_with_measurement": true,
  "measurement_significance": 1.24
}
```

UI：

- 不再显示单一“静止”；
- 显示“Gaia 先验 L / SPHEREx 本次未独立测出”；
- 保留“不是发现声明”。

## 3. 基准工具（只读）

新增 `项目主控/验收/benchmark_official.py`：

- 通过 app `/api/analyze` 跑 5 个官方目标；
- 只读，不写 DB，不改 targets.json；
- 输出 CSV/JSON/Markdown：
  - expected vs actual class；
  - n_epochs/readiness；
  - identity status/RUWE；
  - saturation/quality；
  - catalog prior；
  - pass/data_limited/fail；
- 运行后生成 `项目主控/验收/官方案例基准_report.md`。

判定：

| 状态 | 含义 |
|---|---|
| PASS | 识别结果与官方预期一致，且未超出数据能力 |
| DATA_LIMITED | 数据不够，但明确 U/insufficient，不伪造 |
| FAIL | 结论与官方预期冲突且不是数据限制 |

## 5. 风险

| 风险 | 缓解 |
|---|---|
| 用星表先验“作弊” | 单独字段 `basis=catalog_prior`，不冒充测量 |
| 过拟合 5 个案例 | 规则只用通用 PM 一致性，不写目标名 |
| 星表 PM 不可靠 | RUWE/PM 误差检查；不一致不改 |
| 数据受限案例被误判 FAIL | DATA_LIMITED 单独状态 |
| 页面把先验说成实测 | 文案明确“SPHEREx 本次未独立测出” |
