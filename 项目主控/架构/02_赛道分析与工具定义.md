## 1. 赛道要什么（一句话）

做一个**面向公众的网页工具**：用户输入天区 RA/Dec，工具把该天区的多期 SPHEREx 近红外图像按时间播放成“小视频”，让普通人一眼看出哪些点在动。

### 1.1 硬性验收（4 条）

| # | 要求 | 可执行定义 |
|---|---|---|
| R1 | 用户输入任意 RA/Dec | 不是只支持 5 个预置目标；输入后应显示**该天区**的 SPHEREx 多期图像 |
| R2 | 多期图像 → 时间序列播放 | 至少 2 期；闪烁/播放；能看出位置变化 |
| R3 | 5 个指定天体必须能跑 | Barnard's Star、Epsilon Indi B、WISE 0855、RW Aurigae、R Draconis |
| R4 | 面向公众 | 非天文专业用户能理解；有解释、置信度/不确定性、可证伪条件 |

### 1.2 加分项（官方明说非必需）

1. 跟进新数据发布，易更新；
2. 用好 102 波段 / 6 个探测器阵列；按阵列合图提信噪比；能实时生成光谱更好；
3. 多期相加 / 相减；
4. 视场可调（大视场追快目标，代价是传输慢）；
5. 叠加 Gaia / WISE；
6. URL 带参数，便于嵌入；
7. 显示元数据，如污染标记（contamination flags）；
8. 可借鉴 Astropy（处理）/ Aladin（显示）。

### 1.3 评分含义（我们的解读）

- **R1 是产品核心，不是加分项**：没有“任意坐标 → 真实图像”，就只是一个 5 目标演示器。
- **R3 是验收清单，不是“必须 5 个都检出运动”**：Barnard 会饱和、WISE 太暗、RW/R Dra 是变星/历元不足。**诚实判 U/S/V + 证据**比硬报运动更符合科学，也更能讲出差异化。
- **R4 决定“公众工具”是否成立**：必须有公众语言、置信度、证伪条件；不能只给科研图表。
- **102 波段/光谱是最大加分项，但成本高**：小切片只采样很窄波段；要做实时光谱必须取覆盖色散方向的大切片或整幅，传输/渲染成本高。优先级低于 R1。

## 3. SPHEREx 数据事实（实测，决定工程约束）

- 2025 年起每 6 个月扫全天；**102 个近红外波段**，0.75–5.0 µm；6 个 2040×2040 H2RG 探测器（D1–D3 短波，D4–D6 中波）。
- 像素尺度 **≈6.15″**；单片视场 **≈3.49°×3.49°**（半对角线 ≈2.47°）。
- 单个 level2 文件 **≈65 MB**，7 个 HDU：`PRIMARY / IMAGE / FLAGS / VARIANCE / ZODI / EPSF / WCS-WAVE`。
- `FLAGS` 是污染标记（bit 21 = SOURCE **绝不能屏蔽**，否则把目标自己删掉）；`EPSF` 占切片文件 ~97%，切片服务对它不生效。
- `WCS-WAVE` 是 LVF 波长查找表；同一张图不同行对应不同波长，**小切片只采样窄波段**。
- 访问路径（2026-11-14 实测）：
  - 静态切片 `?center=RA,Dec&size=度` ✅ 200，约 4 MB；
  - S3 公开桶匿名列举/Range ✅；
  - TAP/SIA/DataLink ❌ 502/超时；
  - 422 `Arrays do not overlap.` 可当“免费覆盖判断”。
- 文件名：`level2_<周>_<扫描>_<场号>_<探测器>_spx_<处理版本>.fits`；观测 ID 含下划线，用 `rsplit("_",2)`。
- QR3/DR1 并存；**同一目标时序不要混处理版本**做光度。
- 本地现状：74 条候选历元（5 官方 + 2 样本）、5,893 帧、5,562 曝光、151 周、74 条头、55+ cutout；时间到 2026-10-03。

## 4. 五个官方目标与预期

| 目标 | RA/Dec (deg) | 类型 | 预期 | 真实数据现状 |
|---|---|---|---|---|
| Barnard's Star | 269.452077, +4.693365 | M4V | L（高自行 ~10.3″/yr） | 4 期真实，目标饱和 → S + `SATURATED_SOURCE` |
| Epsilon Indi B | 331.044147, −56.782844 | T1V+T6V | L+O（绕 Eps Ind A，0.30°） | 8 期真实、361 天 → **L3/L**，旗舰 |
| WISE 0855 | 133.795129, −7.245147（赛道坐标；SIMBAD 差 1.6′） | Y2 | L（快速移动） | 8 期真实仅 1 期 3σ → L0/U |
| RW Aurigae | 76.956526, +30.401438 | K1/5e+K5e | V（位置不动、亮度变） | 真实仅 1 个时刻 → HYBRID/V |
| R Draconis | 248.167611, +66.754979 | M4.5-6e | V（Mira，~245 d） | 真实 3 期集中在 1 天 → HYBRID/V |

**关键考点**：RW Aur / R Dra 是反例；不能把“两图相减非零”当移动。工具必须输出“亮度变化，非位置变化”。

## 6. 工具定义（每个工具一个分支、一个 owner）

> 分支统一为 `tool/<name>`，从 `main` 切出；每个子 agent 在 `项目主控/_worktrees/<branch>` 的独立 worktree 工作、提交、推送。  
> 文件所有权见 §7。跨工具改动先回到 `main` 由集成者合并，不在别人分支上直接改。

### 6.1 产品工具

| 工具 | 分支 | 目录 | 一句话 | DoD |
|---|---|---|---|---|
| **MoveScope** | `tool/app` | `系统/app/` | 公众产品：输入坐标 → 多期播放/测量/BIC/判定 | R1 路径可用；5 目标不回归；sample/FOV 无 500；BIC/历元可见；52+ tests |

## 8. 子 agent 工作协议

每个子 agent：

1. 只在自己的 worktree（`项目主控/_worktrees/<branch>`）工作，不切分支、不碰其他 worktree。
2. 先读本工具的提示词/STATUS/审计证据；以当前代码为准。
3. 只改自己拥有的文件；跨工具改动写入报告，不在别人分支改。
4. 每次提交前跑本工具测试/验收；提交信息 `tool: <verb> <what>`；推送到 `tool/<name>`。
5. 不把 `_归档/`、`_worktrees/`、`report/`、日志、缓存提交进仓库。
6. 不伪造 PASS；不确定就标 BLOCKED/WIP。
7. 交付：变更清单、测试命令/输出、未完成/风险、回滚方式。

## 9. 我的循环测试（集成者）

每一轮：

1. `git fetch` 各分支；对每个分支跑该工具的 DoD（见 §6）。
2. 在 `main` 合并通过的分支；对合并后的系统跑 T1 验收 + T3 离线 + T5 启停。
3. 失败 → 给对应子 agent 一条**定制目标**（具体文件/期望/复现命令），不泛泛说“修一下”。
4. 通过 → 更新 `项目主控/验收/report/` 与 `status_matrix.csv`；进入下一轮。
5. 每轮记录：分支、commit、通过项、失败项、下一步。

**硬门槛**：R1、5 目标、无 500、离线 5/5、T1 P0 全绿、3 服务 3/3。

## 10. 风险与优先级

| 风险 | 影响 | 缓解 |
|---|---|---|
| DB 服务停、v1 404 | R1 无法闭环 | 先恢复 DB 分支的 v1，再 T2 |
| T4 P0 缺口 | 头文件入库不安全/不可复现 | 只改 T4 文件，P0-1/2/3 |
| T1 WIP | 没有可信验收 | 先完成 BLOCKED 语义与 R1 用例 |
| 无 git 历史 | 无法回滚 | 本次先 init + push；每分支独立 |
| 多 agent 冲突 | 互相覆盖 | worktree + 文件所有权 + 集成者合并 |
| 102 波段/光谱成本 | 加分项难 | R1/R3/R4 优先；光谱后置 |

**优先级**：DB v1 → T2 → T1 → App 修复 → T6 → T4 → 加分项。
