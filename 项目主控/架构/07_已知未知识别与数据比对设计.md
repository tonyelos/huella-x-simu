## 0. 一句话结论与关键决策

**D 做的是“这个检测源能不能被官方星表解释”，不是“发现新天体”。**

在 6.15″/px 的 SPHEREx 图像上，一个检测源经常是多个星表源的混合；D 的第一原则是**宁可 `ambiguous` / `insufficient_data`，也不硬指派、不把未匹配写成“新恒星”**。

| ID | 决策 | 理由 |
|---|---|---|
| **D-01** | 只输出 6 个顶层状态：`known_star / ambiguous / uncatalogued_candidate / unknown_moving_object / unknown_stationary / insufficient_data`；不新增 `new_star`、`new_planet`、`discovery` 枚举 | 产品边界；任何“发现”表述都超出本项目能力与证据 |
| **D-02** | Gaia DR3 做主星表；2MASS/WISE 做红源颜色与补充；SIMBAD 只做名称/类型；NASA Exoplanet Archive 与 JPL/MPC 为可选排除层 | 各星表的角色不同：Gaia 有 5 参数天体测量；2MASS/WISE 红外颜色强但位置/自行弱；SIMBAD 不是测天体测量星表 |
| **D-03** | 先传播、再匹配：所有星表位置按 PM/视差传播到观测 MJD；查询锥必须留出高自行位移余量（默认 0.3°） | Barnard 的 J2000→J2016 位移约 166″；不传播会错几十角秒，甚至锥搜索都搜不到 |
| **D-04** | 3σ 用二维误差椭圆（Δχ² ≤ 9），不是简单半径；同时看运动矢量残差 | 位置匹配 + 运动一致才算 known；只有位置一致可能是混合/错误对应体 |
| **D-05** | 6.15″/px 下默认“歧义优先”：一个像素内 ≥2 个星表源，或检测孔径污染 >10%，一律 `ambiguous` | 单个 SPHEREx 像素可容纳多颗恒星；亮星质心会被拉偏 |
| **D-06** | DB 拥有 `catalog_release / catalog_source / catalog_match` 的 schema 与持久化；App 拥有分类；只允许单向同步 | 星表是只读参考数据；分类是科学判断，不能让 DB 变成第二科学层 |
| **D-07** | 全量 Gaia 不进单文件 SQLite；只做按场/按锥缓存 | Gaia DR3 约 18.1 亿源；单文件 SQLite 在体积、备份、分发上都不可行 |
| **D-08** | `CATALOG_UNAVAILABLE` 必须与“查询成功但没有匹配”严格区分 | 服务失败时的“空结果”绝不能当成“未收录/新天体” |
| **D-09** | Gaia `source_id` 在 API/JSON/URL/DB 中一律用**字符串** | 64 位整数超过 JavaScript `Number.MAX_SAFE_INTEGER`（9.007e15），用 number 会静默改 ID |
| **D-10** | 没有自行的 2MASS/AllWISE 位置不能单独作为 2025–2026 年的天体测量锚点 | 2MASS 历元约 J2000、AllWISE 约 2010；高自行星 10–25 年可移动数十到数百角秒 |
| **D-11** | `RUWE > 2` 的 Gaia 解降级：误差放大、置信度封顶，必要时 `ambiguous` | Eps Ind B 的 Gaia DR3 `RUWE=4.2955`、`astrometric_excess_noise=5.84`，5 参数解不可当高置信 |
| **D-12** | `uncatalogued_candidate` 只是“未被星表收录的候选”，不是新恒星；UI/API 必须带 `discovery_claim=false` 与证伪条件 | 星表不完备 + 6.15″/px 混合 + 星系/QSO/伪源都会造成“无匹配” |

## 1. 目标、输入、输出与非目标

### 1.1 目标

给定一个检测源/候选源（单历元或多历元），回答四个问题：

1. **位置**：它是否与某个官方星表源在传播后的 3σ 误差椭圆内一致？
2. **运动**：它的多历元运动矢量是否与星表 PM 一致？
3. **身份**：它是不是一个已知的恒星/褐矮星/星表对象？名称、`source_id`、星表版本是什么？
4. **不确定性**：如果无法确认，是“多源歧义”“星表未收录候选”“未解释的运动/静止源”，还是“数据不足”？

输出必须可审计：每个结论都带星表版本、匹配度量、误差、证据、证伪条件。

### 1.2 输入

D 消费 A 的检测源表、B 的星表服务和 C 的任意天区/多历元能力。

```json
{
  "analysis_id": "a1b2c3d4e5f6",
  "field": {
    "ra": 269.452077,
    "dec": 4.693365,
    "fov_deg": 0.25,
    "mjd_min": 60916.656,
    "mjd_max": 61120.279,
    "n_epochs": 4
  },
  "detections": [
    {
      "detection_id": "2025W35_2A_0221_1:D2:s003",
      "epoch_id": "2025W35_2A_0221_1",
      "mjd": 60916.656062,
      "ra": 269.45211,
      "dec": 4.69340,
      "sigma_ra_arcsec": 0.42,
      "sigma_dec_arcsec": 0.42,
      "sigma_corr": 0.0,
      "flux": 12.3,
      "flux_err": 0.4,
      "snr": 30.0,
      "saturated": false,
      "quality": [],
      "method": "psf"
    }
  ],
  "epochs": [
    {
      "epoch_id": "2025W35_2A_0221_1",
      "mjd": 60916.656062,
      "ra": 269.45211,
      "dec": 4.69340,
      "sigma_arcsec": 0.42,
      "snr": 30.0
    }
  ],
  "catalogs": ["gaia", "2mass", "wise", "simbad"],
  "options": {
    "k_sigma": 3.0,
    "search_radius_arcsec": 10.0,
    "include_exoplanet_hosts": false,
    "include_solar_system": false
  }
}
```

**最小可用输入**：

- 至少 1 个检测源，`S/N ≥ 5`，`sigma_ast ≤ 1.5″`（WCS-only 时）或 `≤ 0.6″`（有参考星定标时）；
- 每个检测源有 `mjd`、`ra`、`dec`、位置误差；
- 多历元运动判定需要 ≥2 期；`unknown_moving_object` 至少 2 期、最好 ≥3 期；
- 星表服务可用或本地缓存命中；否则只能输出 `insufficient_data` + `CATALOG_UNAVAILABLE`。

### 1.3 输出状态

顶层 `identification.status` 只允许以下 6 个值：

| 状态 | 含义 | 典型证据 | UI 中文 |
|---|---|---|---|
| `known_star` | 与一个官方星表对象一致，且运动/混合检查通过 | `catalog_id`、3σ 内、PM 一致、无 blend | 已知恒星 |
| `ambiguous` | 多个星表源落在误差椭圆/像素内，或位置对但运动不一致，或 RUWE 高 | `candidates ≥2` 或 `BLEND_RISK` 或 `PM_INCONSISTENT` | 多源歧义 |
| `uncatalogued_candidate` | 星表查询成功但无对应源；多历元静止、PSF 像点源、非混合/非延展 | `catalog_status=ok`、`n_epochs≥2`、`abs(μ)/σ<3` | 未收录候选 |
| `unknown_moving_object` | 多历元显著运动，无法用星表 PM 解释 | `n_epochs≥2`、`abs(μ)/σ>5`、无星表对应 | 未解释的运动源 |
| `unknown_stationary` | 无星表对应、无显著运动，但不像“可申报的点源候选” | 延展、低 S/N、饱和、混合、近亮星、星表不完整 | 未解释的静止源 |
| `insufficient_data` | 数据/星表不足以判定 | <2 期、S/N 低、WCS 差、`CATALOG_UNAVAILABLE`/`PARTIAL` | 数据不足 |

> `known_star` 是“**已知星表点源**”的简写，涵盖恒星与褐矮星（Eps Ind B、WISE 0855）。真正的天体类型由 `catalog.object_type` 决定；UI 对褐矮星显示“已知褐矮星”，不把它误写成“恒星”。这不改变 6 个顶层状态。
>
> 已知太阳系天体（小行星/彗星）**不新增第七个顶层状态**：仍归 `unknown_moving_object`，用 `subtype=known_solar_system_object`、`is_new=false` 区分；UI 显示“已知太阳系天体（非恒星）”，而不是“未知/新天体”。这样既保持 6 标签契约，又不会把已知天体说成发现。

**语义边界**：

- `uncatalogued_candidate` **不是**“新恒星”，只是“在 Gaia/2MASS/WISE 中没有找到对应源，且形态/多历元支持点源”的候选；
- `unknown_moving_object` **不是**“新天体”，可能是小行星、彗星、TNO、褐矮星、双星、伪源或混合；
- `unknown_stationary` **不是**“新星系”，可能是星系、QSO、宇宙线、热像素、混合源；
- 任何状态都不允许输出“新恒星/新行星/发现”结论；`discovery_claim` 恒为 `false`。

### 1.4 非目标

- 不做天体物理分类（不做光谱拟合、不判恒星演化阶段、不做轨道拟合）；
- 不做系外行星凌星/直接成像搜索；
- 不做盲搜索“找新天体”；
- 不把 `uncatalogued_candidate` 升级为“发现”；
- 不让 DB 工具做科学分类；DB 只提供星表数据与候选匹配；
- 不在 D 阶段把全量 Gaia 导入单文件 SQLite。

### 1.5 与 05/06 的衔接

- `05` §3 的 6 个标签与本文一致；本文补充了**二维 3σ、运动残差、混合判定、`CATALOG_UNAVAILABLE` 语义、API/UI 细节**。
- `05` §3.3 把“1 期”一律归为 `insufficient_data`；本文细化为：**1 期且位置匹配唯一、无 blend 时，可以给 `known_star`，但 `motion_check=insufficient`、置信度封顶 0.8；1 期且无匹配时仍是 `insufficient_data`**。这样既保留“不能判运动”的诚实，也允许“认证已知星”的单期产品价值。
- `06` §2 的 A `sources` 数组、B `/api/v1/catalog/...` 是本文的输入契约；若 A/B 最终字段不同，D 以 `schema_version` 适配，不修改 A/B 代码。

### 2.2 Gaia DR3（主）

- **为什么是主**：5 参数解（位置、PM、视差）+ 误差 + `RUWE` + 光度，是唯一能同时做“位置传播 + 运动一致性 + 颜色”的全天星表。
- **参考历元**：`J2016.0`，代码常量取 `MJD 57388.5`（JD 2457389.0）。若官方/实现采用 MJD 57388.0，0.5 d 的差异对 10″/yr 星只有 0.00014″，可忽略；但**必须在 `catalog_release.ref_epoch_mjd` 里写明**，不能假设 J2000。
- **关键列**：`source_id, ra, dec, ra_error, dec_error, pmra, pmdec, pmra_error, pmdec_error, parallax, parallax_error, phot_g_mean_mag, bp_rp, ruwe, visibility_periods_used, astrometric_excess_noise, phot_variable_flag`。
- **质量规则**：
  - `ruwe > 1.4`：误差放大；`ruwe > 2`：降级/歧义（见 §3.3、§3.7）；
  - `visibility_periods_used < 8`：5 参数解不稳，降级（项目阈值，非官方硬门槛）；
  - `astrometric_excess_noise > 2`：误差放大；>5 时原则上 `ambiguous`；
  - `parallax_over_error < 3`：视差不可靠，距离/视差项只作弱约束；
  - `phot_variable_flag='VARIABLE'`：不改变位置匹配，但提示质心/亮度相关，必要时 `BLEND_RISK`。
- **查询**：TAP `https://gea.esac.esa.int/tap-server/tap/sync`，ADQL：
  ```sql
  SELECT TOP 20000 source_id, ra, dec, ra_error, dec_error,
         pmra, pmdec, pmra_error, pmdec_error, parallax, parallax_error,
         phot_g_mean_mag, bp_rp, ruwe, visibility_periods_used,
         astrometric_excess_noise, phot_variable_flag
  FROM gaiadr3.gaia_source
  WHERE 1 = CONTAINS(POINT('ICRS', ra, dec),
                     CIRCLE('ICRS', :ra, :dec, :radius_deg))
  ```
  锥中心用**观测天区中心**，半径必须覆盖高自行位移（默认 0.3°）；不能只按 J2000 目标坐标 0.05° 查。
- **许可**：Gaia 数据按 **CC BY-NC 3.0 IGO** 分发；允许非商业使用与再分发（带署名/许可），但**不能暗示 ESA 背书、不能商业使用**。本项目为非商业挑战赛；不重新分发完整星表，只缓存按场切片与匹配结果。credit line：`ESA/Gaia/DPAC`；引用 Gaia Collaboration 2023。

### 2.3 2MASS（红源/颜色）

- **角色**：J/H/Ks 颜色、亮星交叉证认、WISE 红源补充；**不是** 2025–2026 年的位置锚点。
- **参考历元**：J2000.0；无 PM。
- **使用规则**：
  - 有 Gaia 对应时，2MASS 只提供颜色；
  - 无 Gaia 时，2MASS 位置只能用于“颜色/存在性”提示，不能单独给 `known_star`；
  - 2MASS/WISE 的延展/污染标志（2MASS `contamination`、WISE `ext_flg`）可用于 `EXTENDED`/星系排除。
- **许可**：NASA/IPAC 公开数据，引用 Skrutskie et al. 2006；不暗示 NASA 背书。

### 2.4 WISE / AllWISE / CatWISE2020（红源/运动）

- **角色**：W1/W2 颜色；CatWISE2020 的 PM 可作为无 Gaia 红源（如 WISE 0855）的运动锚点。
- **历元/位置**：
  - AllWISE 源位置约 2010.0；**无 PM**，不能直接与 2025–2026 位置做 3σ；
  - CatWISE2020 星表坐标按 **MJD 57170（2015-05-28）** 给出，带 PM（2010–2018 基线）；可用于传播；
  - CatWISE 的 PM 误差通常 10–30 mas/yr；从 2015.3 传播到 2026 约 10–11 年，误差 0.1–0.3″；对 6.15″/px 足够，但仍比 Gaia 差。
- **使用规则**：
  - 有 Gaia 时，WISE 只做颜色/红源确认；
  - 无 Gaia 但 CatWISE 有 PM 时，可给 `known_star`（`catalog=catwise_2020`），置信度封顶 0.75，并要求 SIMBAD `otype` 支持恒星/褐矮星；
  - 只有 AllWISE 无 PM 时，只能 `ambiguous`/`insufficient_data`，不能 `known_star`。
- **许可**：NASA/IPAC 公开数据；引用 Wright et al. 2010、Cutri et al. 2021、Marocco et al. 2021。

### 2.5 SIMBAD（名称/类型）

- **角色**：把 Gaia/CatWISE 的 `source_id` 映射到名称、`otype`、文献；不提供可靠的 3σ 天体测量（坐标可能是文献均值、不同历元混合）。
- **接口**：CDS TAP `https://simbad.cds.unistra.fr/simbad/sim-tap/sync`；ADQL 用 `basic` + `ident`：
  ```sql
  SELECT TOP 20 b.main_id, b.ra, b.dec, b.otype
  FROM basic AS b
  JOIN ident AS i ON b.oid = i.oidref
  WHERE 1 = CONTAINS(POINT('ICRS', b.ra, b.dec),
                     CIRCLE('ICRS', :ra, :dec, :radius_deg))
  ```
  或按 `source_id` 的交叉证认表（若缓存里有 `ident` 映射）。
- **规则**：
  - SIMBAD 坐标只用于“名称/类型/候选列表”，不进入 3σ 匹配；
  - `otype` 用于 `known_star` 的辅助确认（`star`, `BD*`, `PM*`, `Y*`, `TT*`, `Mi*` 等）；
  - 星系/QSO 类型（`G`, `QSO`, `AGN`）用于 `unknown_stationary`/排除；
  - 频率限制：**<10 查询/秒**；批量按场查一次，不要逐源查。
- **许可**：**ODbL v1.0**（free use, attribution, share-alike for derived databases）；引用 Wenger et al. 2000；不批量再分发 SIMBAD。

### 2.6 NASA Exoplanet Archive（可选：宿主排除）

- **目的**：如果检测源对应一个已知系外行星宿主星，标记 `exoplanet_host=true`，避免把“宿主星附近的无匹配源”误当候选；**不**声称探测到行星。
- **表**：`PSCompPars`（`ra, dec, hostname, pl_name`）或 `stellarhosts`；锥半径 0.1°。
- **规则**：
  - 仅在 Gaia/CatWISE 已确认宿主星时附加 `exoplanet_host`；
  - 不把“宿主星附近”自动当成行星；不输出任何行星结论；
  - 服务失败不阻断识别（降级为 `exoplanet_host=unknown`）。
- **许可**：NASA/IPAC 公开数据；引用 DOI 10.26133/NEA13 / NEA40 与 Christiansen et al. 2025。

### 2.7 JPL Horizons / MPC（可选：太阳系排除）

## 3. 比对算法

### 3.1 检测源误差模型

SPHEREx 的像素尺度项目实测 `scale = 6.15″/px`（官方约 6.2″）；单像素即 PSF 量级。检测源位置误差至少包含：

```text
σ_det² = ( scale * sqrt(σ_x² + σ_y²) + σ_wcs )²
σ_wcs = 0.30″   # 有参考星相对定标（pipeline correction_ok=True）
σ_wcs = 1.50″   # 仅 WCS 投影（correction_ok=False）
σ_floor = 0.05″ # 星表/历元系统误差地板
```

其中 `σ_x, σ_y` 是 A 的质心误差（像素）；`scale` 是 WCS 局部像素尺度。当前 pipeline 的经验值是 `max(hypot(σ_x,σ_y),0.03) + 0.05` px（有定标）或 `+0.25` px（无定标），乘 6.15″/px 后约 0.49″ / 1.72″；D 直接采用 A 的 `sigma_ra_arcsec/sigma_dec_arcsec`，但要求 A 在响应里给出 `sigma_arcsec` 的组成（质心 + WCS 系统项），否则 D 用上面的下限兜底。

**饱和源**：`saturated=true` 时质心可能被 bloom 拉偏；位置误差至少 1 px（6.15″），并加 `SATURATED` 标记；不能给高置信 `known_star`，除非位置匹配极强且星表源明显更亮。

**低 S/N**：`S/N < 5` 不进入识别；`5 ≤ S/N < 10` 只允许 `insufficient_data`/`ambiguous`，不允许 `known_star` 高置信。

### 3.2 PM / 视差传播

#### 3.2.1 基本公式

设星表参考历元 `t0`（MJD），观测历元 `t`（MJD），`Δt_yr = (t - t0) / 365.25`。星表位置 `(α0, δ0)`、`μα* = pmra`、`μδ = pmdec`（mas/yr）、视差 `ϖ`（mas）；观测者质心位置 `r(t) = (X,Y,Z)`（AU）。

```text
Δα* = (μα*/1000) * Δt_yr
      + (ϖ/1000) * ( X sin α0 − Y cos α0 )                 [arcsec]

Δδ  = (μδ/1000) * Δt_yr
      + (ϖ/1000) * ( X cos α0 sin δ0
                   + Y sin α0 sin δ0
                   − Z cos δ0 )                            [arcsec]

α(t) = α0 + Δα* / (3600 * cos δ0)                          [deg]
δ(t) = δ0 + Δδ / 3600                                      [deg]
```

> 极区（`|δ0| > 80°`）不要用 `Δα*/cosδ0` 的除法；改用切平面单位矢量传播，
> 或把星表预测位置与检测位置都投到同一个以天区中心为原点的切平面后再做 3σ。
> 本文的公式用于中低纬；极区实现必须单测。

**符号约定（必须单测）**：

- `(X,Y,Z)` 是**观测者（地球）相对太阳系质心**的位置，不是太阳的地心位置；
- 视位移与观测者位移**反向**：在 `α0=0, δ0=0, ϖ=1000 mas, r=(0,+1,0) AU` 的测试中，应得到 `Δα* = −1.0″`；
- 如果实现使用“太阳地心位置”（`sun_geocentric = −r_observer`），必须把上式整体取反；
- 现有 `系统/app/core/simulator.py:app_positions` 与 `motion.py:parallax_basis` 是仿真内部自洽的低精度实现，**不能直接假定其符号/历元与 ICRS 公约一致**；D 的实现要用上述单测 + Barnard/Eps Ind B 的星表位置回归验证（见 §3.10）。

**地球位置**：低精度太阳历（现有 `earth_position_au` 的思路）精度约 0.01 AU，对应视差误差 ~1% × ϖ；对 ϖ=547 mas 是 ~5 mas，远小于 SPHEREx 质心误差。高阶项（光行差、光线偏折、透视加速度）在 6.15″/px 下可忽略，但要在 `quality_flags` 里标注 `HIGH_PM`，并在验收中检查残差。

#### 3.2.2 高自行与锥搜索

**关键坑**：Gaia DR3 的 `ra/dec` 是 J2016.0 位置，不是 J2000。以 J2000 目标坐标做小锥搜索会漏掉高自行星。

| 星 | J2000 目标坐标 | Gaia DR3 J2016 坐标 | 位移 | 结论 |
|---|---|---|---|---|
| Barnard | 269.452077, +4.693365 | 269.448503, +4.739420 | **≈166″**（几乎全在 Dec） | 0.05° 锥（180″）勉强；0.02° 锥会漏 |
| Eps Ind B | 331.044147, −56.782844 | 331.076453, −56.793812 | **≈75″** | 0.05° 锥可含；0.01° 锥会漏 |
| WISE 0855 | 133.795129, −7.245147 | 无可靠 Gaia DR3 对应源 | 目标 J2000→2026 约 210″；CatWISE 历元 2015.3→2026 约 90″ | 必须用 CatWISE PM；0.05° 锥会漏 |

**锥搜索规则**：

```text
search_radius = max(0.30°, fov_radius + 0.15°)
```

- 对 0.25° FOV，0.30° 足够覆盖 ~10″/yr × 15 yr = 150″（0.042°）的位移，并留出 0.15° 余量；
- 对 3.0° 大 FOV，`fov_radius + 0.15°` 可能到 1.65°；此时要限制 `TOP` 行数、按 `healpix` 分片，不能一次拉全天；
- 锥搜索得到候选后，**必须用传播后的位置**再筛选；不能直接拿星表 J2016 坐标与 2025 图像比；
- 对无 PM 的 2MASS/AllWISE，不能只用其 J2000/2010 位置做 2025 匹配；见 §3.5。

#### 3.2.3 无 PM / 无历元信息

| 星表 | 有 PM？ | 参考历元 | D 的用法 |
|---|---|---|---|
| Gaia DR3 | 是（5 参数） | J2016.0 | 完整传播 + 3σ |
| CatWISE2020 | 是 | MJD 57170（2015-05-28） | 传播；置信度封顶 0.75；误差按 PM 误差放大 |
| 2MASS | 否 | J2000.0 | 只做颜色/交叉证认；不做位置锚点 |
| AllWISE | 否 | ≈2010.0 | 只做颜色；不做位置锚点 |
| SIMBAD | 否（坐标混合） | 文献 | 只做名称/类型 |

**规则**：如果唯一候选来自“无 PM”的 2MASS/AllWISE，位置匹配只能给 `ambiguous`；如果同时有 CatWISE PM 且 SIMBAD 类型支持恒星/褐矮星，可以给 `known_star`（低置信）。

### 3.3 3σ 误差椭圆

#### 3.3.1 协方差

星表位置协方差（简化对角；实现可保留相关项）。**以下全部换算成角秒/角秒²**：

```text
σ_α*²(t) = (σ_α*/1000)² + (Δt_yr * σ_μα*/1000)² + (f_α * σ_ϖ/1000)²
σ_δ²(t)  = (σ_δ/1000)²  + (Δt_yr * σ_μδ/1000)²  + (f_δ * σ_ϖ/1000)²
```

- 星表误差以 mas、mas/yr 给出；除以 1000 换成 arcsec、arcsec/yr；
- `f_α, f_δ` 是 §3.2 公式中 `(X sinα0 − Y cosα0)` 一类无量纲因子（X/Y/Z 以 AU 计）；
- 若保留误差相关项，用星表的 `ra_dec_corr / ra_pmra_corr / ...` 构造完整协方差；D 的第一版允许对角近似，但必须把 `ρ` 置 0 并在质量标记里写 `COV_DIAGONAL`。

**RUWE/质量膨胀**：

```text
k_ruwe   = max(1, (RUWE / 1.4)²)          # RUWE=1.4 -> 1；RUWE=4.3 -> 9.4
k_excess = max(1, 1 + (excess_noise / 2)²)
k_quality = min(25, max(k_ruwe, k_excess))  # 取最大而非相乘，避免双重惩罚
C_cat *= k_quality
```

- 取 `max` 而不是乘积：RUWE 与 excess noise 相关，乘积会把 Eps Ind B 的椭圆放大到不可用；
- 封顶 25（σ 放大 5 倍），既保守又不至于完全失去匹配能力；
- `RUWE > 2` 仍会独立触发 `HIGH_RUWE` 降级（§3.6.2）。

**地板**：`σ_α*, σ_δ ≥ 0.05″`，避免极亮/极精确源让椭圆小到不真实。

检测协方差：`C_det = diag(σ_det², σ_det²)`；若 A 给出 `sigma_corr`，保留相关项：

```text
C = C_cat(t) + C_det
C = [[σ_α*² + σ_det², ρ σ_α* σ_det],
     [ρ σ_α* σ_det, σ_δ² + σ_det²]]
```

#### 3.3.2 判定

```text
Δ = [Δα*, Δδ]                            # 传播后星表 − 检测，角秒
d² = Δᵀ C⁻¹ Δ                            # Mahalanobis
match if d² ≤ k², k = 3                  # 二维 3σ：Δχ²=9
```

- **为什么不是 `sep < 3σ`**：`sep < 3σ` 在一维近似下可以，但二维椭圆有方向；必须用 `d²`；
- **概率**：`p_out = exp(−d²/2)`；`d²=9` 时 `p_out≈1.1%`，即约 98.9% 置信（二维 3σ 椭圆，不是 99.73%）；
- **报告**：`sep_arcsec`、`sigma_major`、`sigma_minor`、`ellipse_pa_deg`、`mahalanobis`、`p_out`、`n_sigma=sqrt(d²)`；
- **多候选**：所有 `d² ≤ 9` 的候选都要进 `candidates`，不能只返回最近的一个。

#### 3.3.3 偶然对齐概率

在 6.15″/px 和银道面高密度区，3σ 椭圆可能随机套住一颗星。计算：

```text
P_chance = 1 − exp(−π * n * a * b)
```

- `n`：局部星表面密度（arcsec⁻²），用锥内星表源数 / 锥面积，或 k 近邻密度；
- `a,b`：误差椭圆半长轴/半短轴（arcsec）；
- `P_chance > 0.10`：加 `CROWDED` 标记；`>0.50`：原则上 `ambiguous`，即使只有一个候选；
- 在银道面 `n≈0.5/arcsec²`、`a=b=1.5″` 时，`P_chance≈97%`，必须歧义优先。

### 3.4 运动矢量残差

#### 3.4.1 观测 PM

对 ≥2 期检测，在切平面做加权最小二乘：

```text
x_i = (α_i − α_ref) cos δ_ref      [arcsec]
y_i = δ_i − δ_ref                  [arcsec]
x_i = x_0 + μ_x (t_i − t_ref)
y_i = y_0 + μ_y (t_i − t_ref)
```

`μ_x, μ_y` 单位 arcsec/yr；协方差 `C_μ,obs` 由 WLS 给出。两期时：

```text
μ = (p_2 − p_1) / (t_2 − t_1)
σ_μ = sqrt(σ_1² + σ_2²) / |t_2 − t_1|
```

#### 3.4.2 与星表比较

```text
μ_cat = [pmra/1000, pmdec/1000]        # arcsec/yr
Δμ = μ_obs − μ_cat
dμ² = Δμᵀ (C_μ,obs + C_μ,cat)⁻¹ Δμ
motion_consistent = dμ² ≤ 9
```

`motion.status` 枚举（API 固定）：

| 值 | 含义 |
|---|---|
| `consistent` | 观测 PM 与星表 PM 在 3σ 内一致 |
| `inconsistent` | 位置匹配但 PM 残差 >3σ |
| `stationary` | 观测 PM 不显著（`abs(μ)/σ_μ < 3`），且无星表对应 |
| `moving` | 观测 PM 显著（`abs(μ)/σ_μ > 5`），且无法用星表 PM 解释 |
| `inconclusive` | PM 不显著或基线太短，不能判运动 |
| `insufficient` | <2 期，无法拟合 PM |

- `motion.significance = abs(μ_obs)/σ_μ`；

- `C_μ,cat` 用星表 PM 误差，乘 `k_ruwe`；
- 只有 `|μ_obs| / σ_μ > 3` 时，PA 才有意义；
- `|μ_obs| / σ_μ < 3`：`motion_status=inconclusive`，不能用 PA 残差否决 `known_star`；
- `dμ² > 9` 且位置匹配：`ambiguous`（可能是混合、未解析伴星、错误对应体），不能 `known_star`；
- 位置匹配 + 运动不一致 + 无其他候选：优先 `ambiguous`，不要直接 `unknown_moving_object`（后者要求“无星表对应”）。

**PA 残差**：

```text
PA = atan2(μ_δ, μ_α*)                  # 北向东
ΔPA = wrap(PA_obs − PA_cat)            # [−180°, 180°]
σ_PA = sqrt( (μ_δ σ_μα)² + (μ_α σ_μδ)² ) / |μ|²
```

- `abs(μ)/σ_μ > 3` 且 `|ΔPA| > 3σ_PA`：`PM_PA_INCONSISTENT`；
- 高自行星（Barnard 10.4″/yr）在 6 个月基线下位移 ~5.1″，PM 可测；低自行星（R Dra 21 mas/yr）在 6 个月基线下位移 ~0.01″，PM 不可测，`motion_status=inconclusive` 是正常的。

#### 3.4.3 加速度/非线性（可选）

≥3 期时拟合线性 + 二次项；若二次项显著（Δχ²>9），加 `ACCELERATING` 标记。可能是双星/未解析伴星/混合，不改变“已知/未知”主状态，但降低 `known_star` 置信度。

### 3.5 颜色、视差、形态与混合

#### 3.5.1 颜色

| 颜色 | 来源 | 用途 | 注意 |
|---|---|---|---|
| `BP−RP` | Gaia | 恒星/褐矮星/红源粗分 | 极暗源可能缺失；消光影响 |
| `J−H`, `H−K` | 2MASS | 红源、褐矮星 | 2MASS 位置不做锚点 |
| `W1−W2` | AllWISE/CatWISE | 红源、褐矮星、星系分离 | W1/W2 饱和/混淆要标记 |
| SPHEREx 102 波段 | SPHEREx | 低分辨率 SED、颜色异常 | D 阶段不做完整 SED 拟合，只做颜色一致性/异常标记 |

**规则**：

- 颜色只做**辅助**，不做硬匹配条件；位置 + 运动是主证据；
- `BP−RP ∈ [−0.5, 4.5]` 且 `W1−W2 ∈ [−0.4, 1.0]`：一般恒星/褐矮星范围；
- `W1−W2 > 1.5` 且无 Gaia：可能是极红褐矮星，也可能是星系/AGN；加 `RED_OUTLIER`，不给高置信 `known_star`；
- `BP−RP < −0.5` 或颜色与星表类型明显矛盾：`COLOR_OUTLIER`，降级/歧义。

#### 3.5.2 视差

- 视差已在传播中使用；这里看**一致性/可靠性**：
  - `parallax_over_error < 3`：`PARALLAX_UNCERTAIN`，距离只作弱约束；
  - `parallax < 0`：星表解不可靠，加 `NEGATIVE_PARALLAX`；
  - `parallax > 1000 mas`：极近星，检查是否 Barnard 量级；传播必须正确；
  - `parallax` 与 SPHEREx 亮度/颜色明显矛盾：提示混合/错误对应，降级。
- 不用视差做“距离必须匹配”的硬门槛（SPHEREx 测光精度不足以支持）。

#### 3.5.3 形态与混合

6.15″/px 下“点源”本身就是一个像素量级；必须显式建模混合：

```text
N_blend = 星表源数 within max(1 px, PSF_FWHM) = 6.15″
if N_blend >= 2: BLEND_RISK = true

f_contam = Σ 星表源流量 within aperture (r_ap=4 px ≈ 24.6″)
if f_contam / f_target > 0.10: APERTURE_CONTAMINATION = true
```

- 流量转换用星表星等 + 颜色近似，不要求精确测光；也可用“亮源计数”替代；
- 若 `BLEND_RISK` 或 `APERTURE_CONTAMINATION`：即使只有一个候选在 3σ 内，也 `ambiguous`；
- 若检测源 `saturated`：`SATURATED`，位置误差放大，不能高置信；
- 若 2MASS/WISE 标志 `extended`/`gal`：`EXTENDED`，优先 `unknown_stationary`，不进入 `uncatalogued_candidate`；
- 若检测源靠近亮星（Gaia `G<10` 在 4 px 内）：`NEAR_BRIGHT_STAR`，PSF 翼/衍射/bleed 风险，降级。

### 3.6 候选合并与歧义处理

#### 3.6.1 跨星表合并

- 同一物理源可能同时出现在 Gaia、2MASS、WISE、CatWISE；用 `source_id` 交叉证认或位置+颜色合并为一个 `candidate`；
- 合并后 `catalog_ids` 是对象：`{"gaia":"...","2mass":"...","wise":"...","catwise":"..."}`；
- 如果不同星表给出**不同**候选（Gaia 一个、2MASS 另一个，位置差 >3σ），不要强行合并；列为多个候选，`ambiguous`。

#### 3.6.2 歧义判定（任一满足）

1. ≥2 个不同物理候选的 `d² ≤ 9`；
2. 一个候选 + `BLEND_RISK`；
3. 一个候选 + `APERTURE_CONTAMINATION`；
4. 一个候选 + `PM_INCONSISTENT` / `PM_PA_INCONSISTENT`；
5. 一个候选 + `RUWE > 2` 或 `astrometric_excess_noise > 5`，且没有独立（SIMBAD/2MASS/CatWISE）确认；
6. `CROWDED` 且 `P_chance > 0.5`；
7. 星表间位置/运动不一致。

#### 3.6.3 不硬指派

- 默认返回 `candidates` 列表，按 `d²` 排序，最多 5 个；
- UI 默认显示“多源歧义，不指派”；用户可手动选择候选，但：
  - `identification.auto_status` 仍保留 `ambiguous`；
  - 手动选择写 `manual_override=true`、`override_catalog_id`、`operator`、`timestamp`；

- 不允许用“最亮”“最近”自动选一个；最近的可能只是混合的另一颗。

### 3.7 分类决策表

设：

- `cat_ok = (catalog_status == "ok")`；`cat_empty` 视为 `ok`（查询成功且 0 行）；
- `n_ep = 有效检测历元数`；
- `n_cand = d² ≤ 9 的不同物理候选数`；
- `blend = BLEND_RISK or APERTURE_CONTAMINATION`；

**`known_star` 的最低条件**：

- `catalog_id` 非空；
- `d² ≤ 9`；
- 无 `blend`；
- 有 ≥2 期且 PM 可测时 `motion_ok`；单期时 `motion_check=insufficient`，置信度封顶 0.8；
- **无 Gaia 时**必须同时满足：CatWISE2020 有 PM（传播到观测历元）、SIMBAD `otype` 支持恒星/褐矮星、无 blend；置信度封顶 0.75；
- **仅 2MASS/AllWISE 无 PM 的位置不能走 `known_star`**（见 D-10）；
- `catalog_status ∈ {ok, stale}`，或 `partial` 且 CatWISE/SIMBAD 独立确认；

**`uncatalogued_candidate` 的最低条件**：

- `catalog_status ∈ {ok, empty}`（所有请求星表都成功，含 0 行）；
- 无候选 `d² ≤ 9`；
- `n_ep ≥ 2`；
- `motion_sig < 3`（没有显著运动）；
- `starlike`：PSF 点源、非延展、非饱和、非近亮星；
- 无 `BLEND_RISK`/`APERTURE_CONTAMINATION`；
- 未命中已知太阳系对象（若启用）；
- 星表深度足够：检测源不能太接近星表极限（否则 `NEAR_CATALOG_LIMIT`，降级为 `unknown_stationary`/`ambiguous`）；
- 置信度 ≤0.6；必须附 `falsifier`。

**`unknown_moving_object` 的最低条件**：

- `n_ep ≥ 2`；
- `motion_sig > 5`（比匹配阈值更严，避免噪声假运动）；
- 无候选 `d² ≤ 9`；
- 排除 WCS 系统误差/混合/变星质心漂移（`WCS_UNCERTAIN`/`FLUX_POSITION_CORRELATION` 时降级）；
- 可选 JPL/MPC 命中：`subtype=known_solar_system_object`，`is_new=false`。

**`unknown_stationary` 的最低条件**：

- 无候选，且不满足 `uncatalogued_candidate` 的“可申报点源候选”条件；
- 典型：延展源、低 S/N、饱和、混合、近亮星、星表不完整、颜色像星系/QSO；
- 例外：1 期但形态明确延展/星系（例如 2MASS `extended` 或 SPHEREx 形态明显非点源）可给 `unknown_stationary`；1 期且无形态证据时仍是 `insufficient_data`（表 3.7 第 4 行）。

### 3.8 伪代码

#### 3.8.1 主流程

```python
def identify(detections, epochs, options):
    # 1. 数据质量门
    det = select_primary_detection(detections)
    if det is None or det.snr < 5 or det.sigma_ast > 1.5:
        return insufficient("LOW_SNR_OR_BAD_ASTROMETRY")

    # 2. 星表查询（带缓存）
    cone = catalog_client.cone(
        ra=det.ra, dec=det.dec,
        radius_deg=search_radius(det, options),   # 默认 0.30°
        catalogs=options.catalogs,
        epoch_mjd=det.mjd,
    )
    if cone.status == "unavailable":
        return insufficient("CATALOG_UNAVAILABLE", catalog=cone)
    if cone.status == "partial" and "gaia" not in cone.ok_catalogs:
        # 除非非 Gaia 独立确认，否则不能判
        return insufficient_or_non_gaia_known(cone, det)

    # 3. 传播 + 候选匹配
    cands = []
    for src in cone.sources:
        p = propagate(src, det.mjd)               # PM + parallax
        C = covariance(src, det, det.mjd)         # 3.3
        d2 = mahalanobis(det, p, C)
        if d2 <= options.k_sigma ** 2:
            cands.append(Candidate(src, p, C, d2))

    # 4. 合并 + 混合 + 偶然对齐
    cands = merge_cross_catalog(cands)
    blend = blend_risk(cone, det)
    crowded = chance_alignment(cone, det, cands) > 0.5

    # 5. 运动
    motion = fit_motion(detections, epochs)       # 3.4
    motion_ok, motion_sig, pa_ok = compare_motion(motion, cands)

    # 6. 分类
    return classify(det, cone, cands, blend, crowded,
                    motion, motion_ok, motion_sig, pa_ok, epochs)
```

#### 3.8.2 传播与匹配

```python
def propagate(src, mjd_obs):
    t0 = src.ref_epoch_mjd
    dt = (mjd_obs - t0) / 365.25
    X, Y, Z = observer_barycentric_au(mjd_obs)       # 注意符号！
    a0, d0 = radians(src.ra), radians(src.dec)
    plx = src.parallax_mas / 1000.0                  # arcsec
    dra = (src.pmra_mas_yr / 1000.0) * dt \
          + plx * (X * sin(a0) - Y * cos(a0))
    ddec = (src.pmdec_mas_yr / 1000.0) * dt \
           + plx * (X * cos(a0) * sin(d0)
                    + Y * sin(a0) * sin(d0)
                    - Z * cos(d0))
    ra = src.ra + dra / (3600.0 * cos(d0))
    dec = src.dec + ddec / 3600.0
    return ra, dec

def covariance(src, det, mjd_obs):
    # 所有输出单位为角秒 / 角秒²
    dt = abs(mjd_obs - src.ref_epoch_mjd) / 365.25
    f = parallax_factor(src, mjd_obs)                # 无量纲，AU
    s_a2 = (src.ra_err_mas / 1000.0) ** 2 \
           + (dt * src.pmra_err / 1000.0) ** 2 \
           + (f * src.plx_err / 1000.0) ** 2
    s_d2 = (src.dec_err_mas / 1000.0) ** 2 \
           + (dt * src.pmdec_err / 1000.0) ** 2 \
           + (f * src.plx_err / 1000.0) ** 2
    k = max(1.0, (src.ruwe / 1.4) ** 2,
            1.0 + (src.excess_noise / 2.0) ** 2) if src.ruwe else 1.0
    k = min(k, 25.0)
    s_a2 = max(s_a2, 0.05 ** 2) * k
    s_d2 = max(s_d2, 0.05 ** 2) * k
    s_det2 = det.sigma_ast_arcsec ** 2
    return [[s_a2 + s_det2, 0.0],
            [0.0, s_d2 + s_det2]]

def mahalanobis(det, ra, dec, C):
    dra = (ra - det.ra) * cos(radians(det.dec)) * 3600.0
    ddec = (dec - det.dec) * 3600.0
    return [dra, ddec] @ inv(C) @ [dra, ddec]
```

#### 3.8.3 分类

```python
def classify(det, cone, cands, blend, crowded,
             motion, motion_ok, motion_sig, pa_ok, epochs):
    n_ep = len(epochs)
    n_cand = len(cands)

    if cone.status == "unavailable":
        return insufficient("CATALOG_UNAVAILABLE", catalog=cone)
    if cone.status == "partial" and "gaia" not in cone.ok_catalogs:
        return non_gaia_or_insufficient(cone, det, cands)

    if n_cand == 0:
        if n_ep == 1:
            return insufficient("SINGLE_EPOCH")
        if motion_sig > 5:
            return unknown_moving(det, motion, cone)
        if starlike(det, cone) and not blend and not crowded:
            return uncatalogued_candidate(det, cone, motion)
        return unknown_stationary(det, cone)

    if n_cand >= 2 or blend or crowded:
        return ambiguous(cands, "MULTIPLE_OR_BLEND")
    if not motion_ok:
        return ambiguous(cands, "PM_INCONSISTENT")
    if cands[0].src.ruwe and cands[0].src.ruwe > 2.0 and not independent_confirm(cands[0]):
        return ambiguous(cands, "HIGH_RUWE")
    return known_star(cands[0], motion_ok, n_ep)
```

### 3.9 边界与降级

| 场景 | 处理 |
|---|---|
| 星表服务超时/502 | `CATALOG_UNAVAILABLE` → `insufficient_data`；不输出“未匹配” |
| Gaia 失败、2MASS 成功 | `partial`；不能 `uncatalogued_candidate`；只有独立确认才 `known_star` 低置信 |
| 锥查询成功但 0 行 | `empty`（不是 unavailable）；可进入无匹配分支 |
| 星表版本变化 | 结果带 `release`；URL 固定 release；不混版本 |
| 只有 1 期 | `known_star` 可（位置唯一、无 blend）；运动相关结论 `insufficient` |
| 检测源在切片边缘 | 位置误差放大/标记 `EDGE`；必要时 `insufficient_data` |
| 饱和 | `SATURATED`；不允许高置信 known；位置误差 ≥1 px |
| WCS-only（无参考星） | `σ_wcs=1.5″`；3σ 椭圆变大；`WCS_UNCERTAIN` |
| 高自行星被锥漏掉 | 增大锥半径；`PM_MARGIN`；验收 Barnard/Eps |
| 多个星表源在 1 px 内 | `BLEND_RISK`；`ambiguous` |
| 星系/QSO | `EXTENDED`/`SIMBAD otype` → `unknown_stationary` |
| 已知小行星/彗星 | 可选命中 → `unknown_moving_object` + `subtype=known_solar_system_object`；不是恒星 |
| 变星质心漂移 | `FLUX_POSITION_CORRELATION` → `ambiguous`/`insufficient`，不误判为运动天体 |
| 宇宙线/热像素 | 形态/多历元不一致 → `unknown_stationary`/`insufficient_data` |

## 4. DB 同步：星表数据层与 App 分类层

### 4.1 职责与所有权

| 数据/能力 | DB 工具 | MoveScope（App） | 禁止 |
|---|---|---|---|
| `catalog_release` | **拥有**：版本、参考历元、许可、引用、导入时间 | 只读展示 | App 自建“星表版本” |
| `catalog_source` | **拥有**：导入、索引、按场缓存 | 只读查询 | App 复制一份 Gaia |
| `catalog_match` | **拥有表/schema/持久化** | **唯一写入者**（异步 POST，opaque payload） | DB 解析/改写分类 |
| 锥搜索/候选匹配 | **提供** `/api/v1/catalog/cone`、`/match` | 调用 | App 直连 Gaia TAP |
| PM 传播/3σ/分类 | 不做 | **拥有** | DB 做科学分类 |

```sql
  match_engine_version TEXT,               -- 如 'd-match/1.0'
  app_version     TEXT,
  created_at      TEXT NOT NULL,
  UNIQUE (analysis_id, detection_id, release_id, catalog_id),
  FOREIGN KEY (release_id) REFERENCES catalog_release(release_id)
);

CREATE INDEX idx_match_analysis ON catalog_match(analysis_id);

CREATE TABLE catalog_cache (
  cache_key       TEXT PRIMARY KEY,        -- sha256(release|ra|dec|radius)
  release_id      TEXT NOT NULL,
  ra              REAL NOT NULL,
  dec             REAL NOT NULL,
  radius_deg      REAL NOT NULL,
  fetched_at      TEXT NOT NULL,
  expires_at      TEXT,
  n_sources       INTEGER NOT NULL,
  status          TEXT NOT NULL,           -- ok|empty|partial|stale
  sha256          TEXT,
  path            TEXT,                    -- 可选：缓存文件相对路径
  FOREIGN KEY (release_id) REFERENCES catalog_release(release_id)
);

CREATE TABLE catalog_import_run (
  run_id          TEXT PRIMARY KEY,
  release_id      TEXT NOT NULL,
  started_at      TEXT NOT NULL,
  finished_at     TEXT,
  n_rows          INTEGER,
  status          TEXT NOT NULL,           -- running|ok|failed
  error           TEXT,
  FOREIGN KEY (release_id) REFERENCES catalog_release(release_id)
);
```

**关键点**：

- `catalog_id` 一律 `TEXT`；Gaia `source_id` 不要存 INTEGER/REAL（SQLite INTEGER 可存 64 位，但 JSON/JS 会丢精度，统一字符串最安全）；
- `catalog_source` 保存的是**参考历元位置**；观测历元的位置由 App 传播，不重复存；
- `catalog_match` 只对**实际候选**写行；无候选的 `unknown_*`/`insufficient_data` 分类不写该表（保存在 App 分析结果/缓存），避免用空 `catalog_id` 伪造一条“匹配”；
- `catalog_match.identification_json` 是 App 的分类快照，DB 只做持久化/审计，不解析、不聚合、不据此重算；
- 索引以 `(release_id, healpix)` 和 `(release_id, zone, ra)` 为主；锥搜索先走带/像素，再在 Python 里做精确球面距离。

### 4.3 单向同步

```text
官方星表（Gaia TAP / IRSA / SIMBAD / NEA / JPL-MPC）
        │ (1) 批量导入 / 按场懒加载
        ▼
DB：star_catalog.sqlite
  catalog_release / catalog_source / catalog_cache
        │ (2) 只读 HTTP：/api/v1/catalog/cone, /match
        ▼
App：识别/分类（PM、3σ、运动残差、ambiguous）
        │ (3) 异步 POST /api/v1/catalog/match（opaque identification）
        ▼
DB：catalog_match（只追加/幂等 upsert；不回写 catalog_source）
```

**硬规则**：

1. 官方星表 → DB 是唯一入口；App 不直连 Gaia/IRSA/SIMBAD（除 B 未实现时的临时 spike，不进演示）；
2. DB → App 只读；App 不写 `catalog_release/catalog_source`；
3. App → DB 只写 `catalog_match`（可选、异步、失败不阻断分析）；DB 不把 match 结果反写星表；
4. 任何“分类”字段只存在于 App 的 `identification` 与 `catalog_match.identification_json`（opaque），DB 不解释；
5. 双向同步、双向覆盖、App 本地 Gaia 副本都禁止。

> “单向”指**星表参考数据**只从官方 → DB → App 流动；`catalog_match` 是分析产物，单独从 App → DB 异步落库，属于审计/持久化，不是第二份星表，也不参与后续匹配。App 只缓存 API 响应/识别结果，不缓存全量星表。

**幂等**：

- `catalog_match` 以 `(analysis_id, detection_id, release_id, catalog_id)` 唯一；
- App 重试用同一 `match_id`/唯一键 upsert；DB 不重复插入；
- `analysis_id` 由 App 生成；DB 只校验非空/长度。

### 4.4 按场缓存与离线

- **缓存粒度**：DB 按“锥”缓存参考历元星表（`release|ra|dec|radius`），不按每个 MJD 重复缓存；App 负责传播；
- **空间索引**：HEALPix `nside=64`（约 0.84 deg²/像素）做粗定位，`zone+ra` 做条带；锥搜索先取像素并集，再精确过滤；
- **预热门场**：7 个预设场在演示/验收前预拉 0.3° 锥；20 随机天区按需懒加载；
- **TTL**：
  - 静态 release（Gaia DR3）缓存不自动过期；release 变更才失效；
  - 在线 TAP 临时查询缓存 30 天；`stale` 仍可用于身份判定，但 UI 标注；
  - 负缓存（0 行/失败）5 分钟，避免打爆 TAP；
- **离线**：
  - T3 冻结时把 7 场 + 演示自定义坐标的锥缓存、`catalog_release`、manifest（sha256）一起冻结；
  - 断网时只读缓存；`catalog_status=ok`（缓存新鲜）或 `stale`（过期但可用），`cache.hit=true`、`network=false`；
  - 缓存未命中 → `CATALOG_UNAVAILABLE`，UI 明确“无法判断”，不是“未收录”；
- **缓存不变量**：缓存响应必须带 `release_id`、`ref_epoch_mjd`、`fetched_at`、`n_sources`；App 校验 release 与请求一致，否则拒绝混用。

### 4.5 `CATALOG_UNAVAILABLE` 语义

| 情况 | DB 响应 | App `catalog_status` | App `identification.status` | UI |
|---|---|---|---|---|
| 全部星表成功，锥内有源 | `200 ok` | `ok` | 正常分类 | 正常 |
| 全部星表成功，锥内 0 源 | `200 empty` | `empty`（视为 ok） | 可进入无匹配分支 | “星表查询成功，无对应源” |
| 部分星表失败/超时 | `200 partial` + `catalogs[].status` | `partial` | 不能 `uncatalogued_candidate`；Gaia 缺失时 `insufficient_data` | “部分星表不可用” |
| 全部失败/超时/502 | `503 CATALOG_UNAVAILABLE` | `unavailable` | `insufficient_data` + `reason=CATALOG_UNAVAILABLE` | “星表不可用，无法判断” |
| 限流 429 | `429 RATE_LIMITED` | `unavailable`（retryable） | `insufficient_data` | “请求过多，稍后重试” |
| 本地缓存命中但过期 | `200 stale` | `stale` | 可分类，置信度封顶 0.9 | “缓存（N 天前）” |
| 缓存未命中 + 断网 | `503 CATALOG_UNAVAILABLE` | `unavailable` | `insufficient_data` | “离线且无缓存” |

**反例（必须测试）**：

- 星表 503 时返回 `uncatalogued_candidate` → **FAIL**；
- 星表 503 时 UI 显示“未收录/新星” → **FAIL**；
- `partial` 时把 Gaia 缺失当成“无匹配” → **FAIL**；
- `empty` 时把“查询成功 0 行”当成“服务失败” → 过度保守但不是错误；要区分文案。

### 4.6 为什么全量 Gaia 不进单文件 SQLite

- Gaia DR3 约 1.81e9 行；即使每行 100–200 B，也是 **200–400 GB** 量级；SQLite 单文件在备份、VACUUM、分发、并发读上都不合适；
- 2MASS 4.7e8、AllWISE 7.5e8、CatWISE 1.9e9；全部塞入更不可行；
- 本项目只需要“演示场 + 任意天区按需锥”：
  - 0.3° 锥面积约 0.28 deg²；Gaia 平均密度约 4.4e4/deg² → 约 1.2e4 行；银道面可到 1e5–5e5 行，SQLite 仍可控；
  - 7 个预设场 + 20 随机场，合计远小于全量；
- 如果未来要全天离线：
  - 按 HEALPix 分区（如 nside=16/32）切 Parquet/DuckDB，而不是单文件 SQLite；
  - 或保留 Gaia TAP 在线查询 + 本地按场缓存；
  - 或使用外部专业服务；
- **D 的验收只要求按场缓存可复现，不要求全天离线**。

### 4.7 版本、迁移、回滚

- `release_id` 不可变；新版本新增行（`gaia-dr4` 未来），不覆盖 `gaia-dr3`；
- `catalog_match.release_id` 记录当时用的版本；App 结果里也带 `release`；
- schema 版本：`PRAGMA user_version = 1`；迁移脚本只加列/加表，不删旧列；
- 回滚：保留上一版 `star_catalog.sqlite` 快照 + manifest；App 按 release 固定；
- 验收前冻结 release；演示期间不改星表版本。

### 4.8 安全、限流、可观测

- DB API 默认 `127.0.0.1`；只读端点无鉴权（本机演示）；`POST /catalog/match` 用本地 token/仅本机；
- 限流：每 IP 10 req/s；Gaia TAP 串行 ≤2 并发；失败重试 2 次，指数退避 1/4/9 s；熔断 5 次失败/5 min；
- 记录：`request_id`、`release`、`cache_hit`、`upstream_ms`、`n_rows`、`error_code`；
- 不在日志里写完整星表行；只写计数与摘要。

## 5. API 与 UI 契约

### 5.1 通用约定

- JSON UTF-8；时间 UTC ISO-8601；角度度；角秒显式 `_arcsec`；MJD 显式 `_mjd`；
- 所有响应带 `schema_version: "1.0"`；星表相关响应带 `release`/`catalogs[].release`；
- `source_id`/`catalog_id` 一律字符串；
- 错误体：
  ```json
  {
    "error": {
      "code": "CATALOG_UNAVAILABLE",
      "message": "Gaia TAP 查询超时，已重试 2 次。",

      "retryable": true,
      "retry_after_s": 30,
      "cache": {"hit": false, "stale": false, "last_success": null}
  ```

- 分页：`limit/offset`；锥查询默认 `limit=5000`，最大 `50000`；超过时必须提示“缩小半径/增加过滤”，不能静默截断后当完整星表。

- 手动选择候选时：`auto_status` 保留自动结果（通常是 `ambiguous`），`manual_override=true`、`override_catalog_id`、`operator`、`timestamp`；`status` 不得被手动改成 `known_star` 后丢失 `auto_status`；
- `candidates` 最多 5 个，含 `catalog_id`、`sep`、`mahalanobis`、`pm_residual`、`ruwe`、`quality`；
- `quality` 是累加数组，不允许覆盖；
- 顶层 `identification` 对应“锁定/主检测源”；没有主源时为 `null`，但 `sources[].identification` 仍可存在。

### 5.5 错误码与 HTTP 状态

| HTTP | `error.code` | 含义 | App 映射 |
|---|---|---|---|
| 400 | `INVALID_RA`/`INVALID_DEC`/`INVALID_RADIUS` | 参数非法 | 400，修请求；不降级 |
| 400 | `INVALID_CATALOG` | 未支持星表 | 400 |
| 404 | `CATALOG_NOT_FOUND`/`SOURCE_NOT_FOUND` | release/source 不存在 | 提示版本/ID 错误 |
| 409 | `RELEASE_MISMATCH` | 请求 release 与缓存/DB 不一致 | 拒绝混用，要求刷新 |
| 413/422 | `TOO_MANY_ROWS` | 锥太大/结果超限 | 缩小半径/视场 |
| 429 | `RATE_LIMITED` | 限流 | `CATALOG_UNAVAILABLE`（retryable） |
| 502 | `CATALOG_UPSTREAM_ERROR` | 上游失败 | `CATALOG_UNAVAILABLE` |
| 503 | `CATALOG_UNAVAILABLE` | 星表不可用 | `insufficient_data` + `CATALOG_UNAVAILABLE` |
| 504 | `CATALOG_TIMEOUT` | 超时 | `CATALOG_UNAVAILABLE`（retryable） |

### 5.6 URL 与锁定

**优先 URL**：

```text
/?target=barnard&source_id=4472832130942575872&catalog=gaia-dr3&lock=1&fov=0.25
```

- `source_id` 是字符串；`catalog` 固定 release；
- 页面加载时优先按 `source_id` + `catalog` 精确取源；取不到 → 明确错误“该 source_id 不属于当前星表版本”，可回退到 `ra/dec` 但必须提示；
- 无 `source_id` 时：
  ```text
  /?ra=269.452077&dec=4.693365&fov=0.25&lock=1
  ```
- 点击源 → 高亮 → “锁定” → URL 更新；浏览器前进/后退可复现；
- URL 中坐标保留全精度（不要 `toFixed(5)`）；`source_id` 不要用 number；
- 锁定状态刷新后保持一致；如果星表 release 变化，提示“星表版本已更新，是否按新版本重查？”不静默改 ID。

### 5.7 UI 源卡片与状态机

**源卡片结构**（从上到下）：

1. **状态徽章**：`known_star` 绿 / `ambiguous` 琥珀 / `uncatalogued_candidate` 蓝虚线 / `unknown_moving_object` 紫 / `unknown_stationary` 灰 / `insufficient_data` 灰点；
2. **身份**：名称、`source_id`（可复制）、星表/release、`object_type`；
3. **位置/运动**：检测坐标、传播后星表坐标、sep、3σ 椭圆、PM/视差、运动状态；
4. **候选列表**：`ambiguous` 时显示 2–5 个候选，按 `d²` 排序，标 `RUWE`/`BLEND`/`PM` 风险；
5. **证据**：2–4 条中文短句，引用具体数值；
6. **证伪条件**：一句“什么情况下这个结论会失效”；
7. **星表状态**：`ok/empty/partial/stale/unavailable` + 缓存时间；离线徽章；
8. **免责声明**：固定文案，不可隐藏。

**状态机**：

```text
idle
  → loading_catalog
  → matching
  → known_star | ambiguous | uncatalogued_candidate
    | unknown_moving_object | unknown_stationary | insufficient_data
  → (catalog_unavailable | catalog_partial | catalog_stale) 作为并行状态
```

- `loading_catalog` 时显示“正在查询 Gaia DR3…”；>10 s 显示“星表响应较慢，可重试/离线缓存”；
- `catalog_unavailable` 不是最终科学状态；最终状态必须是 `insufficient_data`，并说明原因；
- `ambiguous` 时禁止自动展开某个候选为“已确认”；用户点击候选只改变高亮/锁定，不改变 `auto_status`。

**锁定交互**：

- 源标记点击 → 选中；再次点击/锁定按钮 → 固定；
- 锁定后刷新页面仍选中；URL 可分享；
- 锁定不改变分类，只改变“当前查看对象”；
- 切换源时保留视场/时间轴，不重置分析。

**离线/降级**：

- `catalog_status=stale`：顶部黄条“星表缓存：Gaia DR3，15 天前”；结果可用；
- `catalog_status=unavailable`：顶部红条“星表不可用，无法判断已知/未知”；源卡片只显示检测信息 + `insufficient_data`；禁止显示“未收录”；
- `partial`：黄条“部分星表不可用（2MASS 超时）”；如果 Gaia 可用，仍可 known，但 `confidence` 降；如果 Gaia 不可用，原则上 `insufficient_data`；
- 断网：只读缓存；没有缓存时明确“离线且无缓存”；
- “重试”按钮：只重试失败星表，不重跑检测。

### 5.8 文案与合规

**必须出现**：

- “未匹配不等于新恒星/新天体。”
- “6.15″/px 下多个星表源可能落在同一像素，系统不硬指派。”
- “本工具只做已知/未知比对，不做发现声明。”

**禁止出现**（正向断言）：

- “发现新恒星”“新恒星”“新行星”“新天体”“首次发现”“discovery”；
- “未收录 = 新星”；
- “最亮的就是对应体”；
- “星表没有 = 不存在”。

**`uncatalogued_candidate` 文案**：

> 在 Gaia/2MASS/WISE 中没有找到对应源；该源在多期图像中位置稳定、形态像点源。它只是“未收录候选”，可能是星表遗漏、星系/QSO、伪源或混合，**不是新恒星**。

**`unknown_moving_object` 文案**：

> 多期图像显示该源在移动，但无法用已知恒星 PM 或已知太阳系天体解释。可能是小行星、彗星、TNO、褐矮星、双星或伪源；**不是发现声明**。

**`ambiguous` 文案**：

> 在 3σ 椭圆/一个 SPHEREx 像素内有多个星表源，系统无法可靠指派。请查看候选列表；不要把它当成已确认的已知星。

### 6.2 20 个随机天区

**选择方法**（可复现）：

- 固定随机种子（建议 `20261115`），从全天均匀采样 20 个 RA/Dec；
- 分层，避免全在银道面或全在高纬：
  - 6 个 `|b| < 15°`（拥挤/高密度）；
  - 8 个 `15° ≤ |b| < 45°`；
  - 4 个 `|b| ≥ 45°`（含 1 个南极/北极附近）；
  - 2 个“无本地 SPHEREx 覆盖”的对照；
- 每个场先用 C 的覆盖查询判断是否有本地历元：
  - 有覆盖：跑 2–4 期识别；
  - 无覆盖：期望 `NO_LOCAL_COVERAGE`/`insufficient_data`，不能伪造星表结论；
- 记录种子、场坐标、release、MJD、结果，写入验收报告，保证可复现。

**通过标准**：

- 20/20 无 500；每场都有 `catalog_status` 与 `identification`（或明确的 `NO_LOCAL_COVERAGE`）；
- 有本地覆盖 + 星表可用的场：≥80% 的 `S/N≥10` 源有非 `insufficient_data` 状态；
- 星表不可用场：100% `insufficient_data`/`CATALOG_UNAVAILABLE`，0 条 `uncatalogued_candidate`；
- 星表空场：`empty` 与 `unavailable` 文案不同；空场检测源可以是 `uncatalogued_candidate`（若多期、点源、无混合），但必须标 `NEAR_CATALOG_LIMIT` 风险；
- 所有结果带 `release`；跨场不混 release；
- 误报率：人工抽查 20 场中 `known_star` 的 30 个源，位置残差应 <1.5″；发现 >3″ 的错误对应体即 FAIL。

### 6.4 离线缓存

- **前置**：在联网状态预拉 7 场 + 20 场中至少 7 个有覆盖场；记录 `release`、`fetched_at`、`sha256`；
- **断网**：关闭网络/黑洞代理；只读缓存；
- **期望**：
  - 7/7 场可跑；
  - `catalog_status ∈ {ok, stale}`（缓存新鲜为 `ok`，过期但可用为 `stale`）；
  - 与联网结果的 `status` 一致率 ≥95%；差异只允许出现在 `confidence`/`cache` 字段；
  - 0 次网络请求（用代理日志/`strace`/应用计数验证）；
  - 缓存未命中场：`insufficient_data` + `CATALOG_UNAVAILABLE`，不是“未收录”；
- **复现**：同一 release + 同一 manifest + 同一检测输入 → 同一 `identification`（除时间戳/`analysis_id`）。

### 7.3 风险矩阵

| 风险 | 概率 | 影响 | 触发信号 | 缓解 |
|---|---|---|---|---|
| **6.15″/px 混合** | 高 | 高：错配/假 known | 1 px 内多 Gaia 源；孔径污染 >10% | `BLEND_RISK`/`APERTURE_CONTAMINATION` → `ambiguous`；不硬指派；RW Aur 用例 |

### 7.4 未决问题

1. **A 的 `detection_id` 稳定性**：跨历元/跨分析是否稳定？如果每次分析重新生成，`catalog_match` 的幂等键需要改用 `(analysis_id, epoch_id, x, y)` 或 A 提供稳定 ID。
2. **B 的 `/match` 边界**：B 是否做 PM 传播？建议 B 只返回参考历元行 + 可选 `ra_pred`；D 做传播/3σ/分类。若 B 也做，必须共享 `match_engine_version` + 同一 fixture，避免两套结果。
3. **WISE 0855 的 CatWISE 缓存**：7 场预热是否包含 CatWISE 行？若没有，验收允许 `ambiguous`，但产品上应补。
4. **Eps Ind B 的验收口径**：RUWE 4.3 下是否接受 `ambiguous`？本文建议接受；若产品要求 `known_star`，必须引入外部（SIMBAD/2MASS/轨道）确认，不能只靠 Gaia 5 参数。
5. **太阳系天体的顶层标签**：是否新增第七个 `known_solar_system_object`？本文为保持 6 标签，使用 `unknown_moving_object + subtype`；若产品/验收更倾向于独立标签，需要改契约版本。
6. **手动选择候选的权限**：是否允许用户手动锁定某个候选并显示为 known？本文建议允许展示/锁定，但 `auto_status` 保持 `ambiguous`，验收不采信手动结果。
7. **Gaia DR4 时间**：若 DR4 在 D 实现期间发布，是否切换？本文建议固定 DR3 到验收结束；DR4 作为新 release 后续接入。
8. **全天离线**：D 只做按场缓存；全天离线需要 C/基础设施的 Parquet/DuckDB 分区方案，不在 D 范围。
9. **WCS 参考系**：SPHEREx WCS 是 ICRS astrometric 还是 apparent？当前按 ICRS 处理；需用亮星残差验证，若含光行差需在传播中扣除 ~20″。
10. **`uncatalogued_candidate` 的星表深度门槛**：如何量化“星表足够深”？建议 B 返回 `limiting_mag`/`completeness`，或用场内 Gaia G 分布 90 分位；未定。
