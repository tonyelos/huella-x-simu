## 2. 目标物理结构（推荐）

**原则：只移动，不改代码内部相对关系；保留三个工具的原名，避免 import/路径大面积断裂。**

```text
huellaX/
├── README.md                     # 新入口：系统 / 项目主控 / 参考
├── 系统/                         # 运行系统（monorepo，层内相对路径保持不变）
│   ├── app/                      # MoveScope 产品
│   ├── 数据库工具/                # SQLite + Blob 数据层
│   ├── 视图工具/                  # 天区选择器
│   ├── docs/                     # 理论/实现/实测文档
│   ├── tools/                    # find_epochs / scan_week_index / validate
│   └── 参考 资料/                 # 赛道、数据访问笔记、样本
├── 项目主控/                      # 控制面（不动 code）
│   ├── README.md
│   ├── 01_验收基线与结果.md
│   ├── 02_架构设计与集成契约.md
│   ├── 03_额外工具建议.md
│   ├── 架构/                     # 本目录：基础架构、迁移记录、ADR
│   ├── 提示词/                    # 统一提示词索引
│   ├── 验收/                      # T1（WIP）
│   ├── 冻结/                      # T3（已验收 5/5）
│   ├── 启动/                      # T5（sandbox 验收）
│   ├── evidence/                  # 审计证据
│   └── _归档/                     # 迁移前快照、未验证中间文件
└── .gitignore
```

**为什么这样放：**

- `app/`、`数据库工具/`、`视图工具/` 仍是同级；`数据库工具` 的 `TOOL_ROOT.parent`、`视图工具` 的 `../app`、`app` 的 `../参考 资料` 都仍然成立。
- `docs/`、`tools/`、`参考 资料/` 一并进入 `系统/`；`app/server.py` 的 `ROOT/docs`、`find_epochs.py` 的 `ROOT/app/data`、数据库的 `WORKSPACE/参考 资料` 都仍然成立。
- 控制面独立，不和运行时代码混放。
- 不重命名三个工具，避免 `app.core`、`db.*`、`../app` 的连锁修改。
