# 三模块联动计划：视图 → 分析 → SQL

> 目标：视图模块作为第一层选择“区域 + 时间”，把参数传给分析层（cascade/tracks），SQL 数据模块作为后台提供历元/覆盖。
> 边界：联动是产品/数据契约，不改变“候选不是确认”的科学边界。

---

## 0. 数据流

```text
视图 View（8830）
  选择 RA/Dec/FOV + 时间窗口 [t0,t1]
    │  链接带参数
    ▼
分析层 App（8790）
  /cascade 或 /tracks
  按时间窗口过滤历元
    │  data_layer / DB v1
    ▼
SQL 数据模块（8797）
  epochs/coverage/frames
```

原则：

- 视图只负责“选区域/选时间/跳转”，不做分析；
- 分析层负责“按时间窗口过滤 + cascade/tracks”；
- SQL 模块只提供数据/覆盖，不做分类；
- 任何一层失败都不能伪造数据。

---

## 1. 视图层（View）

新增：

1. 时间窗口控制：
   - 当前 `state.mjd` 作为中心；
   - 窗口 `±N 天`（默认 365；可选 30/90/180/365/730）；
   - 显示 `t0/t1`（MJD/UTC）；
   - 链接参数 `t0,t1`。
2. 两个入口：
   - “进入级联 / 残差” → `/cascade?ra=&dec=&fov=&t0=&t1=&from=view`
   - “进入轨迹发现” → `/tracks?ra=&dec=&fov=&t0=&t1=&from=view`
3. 保留原“在 MoveScope 打开”（单目标分析）。
4. URL 深链支持 `t0/t1`，刷新可复现。

验收：

- 选 Barnard、窗口 30 天，链接参数正确；
- 打开分析页，时间窗口显示且少于默认历元；
- 无 JS error。

---

## 2. 分析层（App）

新增：

1. `/cascade`、`/tracks` 读取 `t0/t1`（MJD）：
   - 过滤 `data_layer.build_dataset` 返回的 epochs；
   - 响应带 `time_filter: {t0,t1,requested,kept}`；
   - 0 历元时 200 + 空结果 + 可读说明，不 500；
   - 1 历元时 tracks 返回 `insufficient`，不伪造运动。
2. UI：
   - 显示“来自视图 / 时间窗口 MJD x–y / 保留 N/M 期”；
   - 保留手动修改区域/时间；
   - 链接回视图。
3. API `/api/cascade`、`/api/tracks` 接受 `t0/t1`（或 `mjd_min/max`），带 filters 字段。
4. 测试：
   - 时间过滤、0/1/多历元；
   - URL 参数；
   - 旧 URL 无 `t0/t1` 不回归。

验收：

- Barnard 默认 4 期；t0/t1 限制到 2025-08-29–2025-09-05 时只保留 2 期；
- tracks 仍可运行或明确 `insufficient`；
- app 227+ tests 不回归。

---

## 3. SQL 数据模块（DB）

新增：

1. `GET /api/v1/epochs` 支持 `mjd_min/mjd_max`：
   - 对 `target_epochs` 过滤 `mjd`；
   - 响应带 `time_filter`、`count`；
   - 与 `target_id` / `ra,dec` 兼容。
2. `GET /api/v1/coverage` 可选支持 `mjd_min/max`，统计窗口内 frames/epochs。
3. 测试：
   - Barnard 窗口 2 期/全部 4 期；
   - 无窗口保持原结果；
   - 非法 MJD 400；
   - DB 76+ tests 不回归。

验收：

- `/api/v1/epochs?target_id=barnard&mjd_min=...&mjd_max=...` 返回 2 条；
- 无参数返回 4 条；
- T1 G 组不回归。

## 5. 任务/分支/排期

| 任务 | Owner | 分支 | 交付 |
|---|---|---|---|
| View 时间窗口 + 分析入口 | view-owner | `tool/view` | 时间控件、两个链接、URL 深链、测试 |
| App 时间过滤 + UI | identify-owner | `tool/identify` | `/cascade`/`/tracks` t0/t1、响应、测试 |
| DB 时间过滤 API | db-owner | `tool/db` | `/api/v1/epochs` 过滤、测试 |
| 联动验收 | lead + T1 | main | Ego/T1/T6 |

排期：2–4 天；三个分支互不冲突。

---

## 6. 风险

| 风险 | 缓解 |
|---|---|
| 时间窗口太小，0/1 期 | 明确 `insufficient`，不伪造 |
| 视图时间 slider 和数据时相混淆 | UI 标“分析窗口 ±N 天”，与当前时刻分开 |
| 跨波段/不同 release | 维持现有过滤；不混测光 |
| URL 参数过长/丢失 | 只用 ra/dec/fov/t0/t1/from |
| 视图/分析/DB 版本漂移 | T1/T6 检查；响应带 schema/time_filter |
