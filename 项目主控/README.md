## 0. 审计快照（2026-11-14 23:07）

1. **三个工具都不弱，但还不是一套系统。**
   - `app/` 是唯一进验收的产品；Epsilon Indi B 的真实数据结果是全项目最强资产。
   - `数据库工具/` 工程质量最高（27 测试全过、导出逐项对账通过），但运行时无人调用——它是离线物化视图，不是数据层。
   - `视图工具/` 最好看，但只负责“选天区”，与 MoveScope 的交接链路三处同时断（路径、HEAD、坐标精度）。

2. **官方 4 条硬要求：1 未达标、1 达标、2 部分达标。**
   - **R1 任意 RA/Dec 看真实多期图像：❌ 未达标。** 自定义坐标只生成模拟时序；即使输入 Barnard 精确坐标、数据库里有 4 期真实历元，仍返回 `mode=synthetic`。
   - **R2 多期播放：✅ 达标。**
   - **R3 5 个指定天体：🟡 部分。** 5/5 都能跑，但只有 3/5 用真实数据，只有 **Eps Ind B** 是真实数据上的正确运动检测；Barnard 饱和判 S，WISE 只有 1 期判 U，RW/R Dra 是 HYBRID。
   - **R4 面向公众：🟡 部分。** 中文解释、置信度、证伪条件很好；但仅本机/仅中文/无引导，研究者模式的 BIC 面板实际不可见。

3. **最大的产品风险不是算法，是“任意坐标没有真实数据通路”。**
   数据库已经有 `frames`、`target_epochs`、cone、coverage，正是缺的那块；接上它，R1 才能从 FAIL 变 PASS。

4. **最大的演示风险是“5 个目标只有 1 个真实动了”。**
   不要为了好看去调参/放宽显著性；应在演示里主动解释 Barnard 饱和、WISE 太暗、RW/R Dra 真实历元不足。诚实是加分项，但必须讲出来，否则会被当成 4 个失败。

5. **需要额外工具，但不是第四个产品，而是控制面：**
   - **P0**：数据桥接（接 R1）+ 验收/契约工具（证明能提交）。
   - **P1**：离线演示冻结器（防 IRSA 502）+ 统一启动器（防端口错）+ 头文件采集器（若要讲“持续更新”加分项）。
   - **P2**：漂移检查器（并入验收）。
   - **不要做**：第四个 UI、第二个数据库、现在做完整光谱/Gaia 叠加/盲搜索。

6. **当前未达提交门槛，但大部分是 1–2 天的接线/校验/可见性问题，不是重写。**
   先做 R1 接线与验收工具；不要先加新功能。

## 7. 架构一句话

> **数据库管“有没有、在哪、什么时候”；MoveScope 管“动没动、为什么”；项目主控管“算不算过”。视图工具只是可选的“看天区”入口。**

目标架构四平面：

```
L4 控制面  项目主控（契约/验收/冻结/启动/快照）
L3 体验面  MoveScope Web（唯一入口）+ 可选视图工具
L2 计算面  MoveScope core（取切片/测光/定标/关联/BIC/判定）
L1 数据面  数据库工具（targets/frames/epochs/cutouts/blobs/coverage）
L0 数据源  IRSA 静态切片 · S3 公开桶 · SIMBAD 参考
```

契约、DTO、就绪度拆分、失败矩阵、迁移顺序见 [02_架构设计与集成契约.md](02_架构设计与集成契约.md)。

## 9. 工作方式（项目主控的规矩）

1. **先证据，后结论**：任何“已修复/已达标”必须附命令与输出；没有证据的只算“声称”。
2. **一个事实源**：目标/历元/覆盖只认数据库；JSON 是导出缓存，不是第二源。
3. **契约变更走验收**：改字段/改口径必须先过 `check_compat` + 验收工具；不许“先改了再说”。
4. **冻结后只修 P0**：演示前 24 小时冻结；除阻断性 bug 外不改代码。
5. **诚实是产品能力**：REAL/HYBRID/SIM、L0–L3、证伪条件必须显式；不允许静默降级。
6. **不做第四件事**：当前阶段只做 R1 接线、验收、离线；新功能一律排到提交后。
