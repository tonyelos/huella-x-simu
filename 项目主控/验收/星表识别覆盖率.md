# 星表识别覆盖率审查

> 问题：当前星表识别是“多数可以”，还是只标注案例？
> 结论：**当前生产配置只标注案例/被选中源，不是多数；即使换成完整 Gaia 缓存，也只能覆盖已检测源的一部分，不能识别多数恒星。**

---

## 1. 当前生产配置

| 项 | 当前值 |
|---|---|
| B 星表服务 8799 | **250 行 fixture**（7 场） |
| `catalog_status` | **partial** |
| 全部 Gaia 源 | 250 |
| C Barnard 单期检测源 | 47 |
| B 对 47 个 C 源的批量匹配 | **0 matched / 47 no_match** |
| Tracks D1 | **0**（B partial，D1 不给） |
| 官方 5 目标身份 | Barnard known；Eps ambiguous；WISE insufficient；RW ambiguous；R Dra known |
| 批量识别 UI | **没有**；只有目标卡/点击源走 `/api/identify` |

当前 B 8799 的 `catalog_status=partial`，并带警告：

> 至少一个检测点位于 fixture/场边缘缓存；缺失的星表源不会出现在候选中，`catalog_status=partial`；0 候选不等于未收录/新天体。

所以当前不是“多数可识别”，而是：

```text
目标卡 / 点击源 → 单点识别
大多数检测源 → 未批量匹配
D1 轨迹 → 0
```

---

## 2. 换成完整 Gaia 缓存会怎样

用 B 8801 真实 17,679 源缓存（临时启动，测完已停止），对同一组 47 个 C 源做 3″ 批量匹配：

| 状态 | 数量 | 占 47 |
|---|---:|---:|
| 单候选 `single_candidate` | **31** | 66% |
| 多候选 `ambiguous` | **6** | 13% |
| 无匹配 `no_match` | **10** | 21% |
| 合计有候选 | **37** | **79%** |

解释：

- **79% 的已检测源**至少有一个 Gaia 候选；
- 但只有 **31/47（66%）** 是单候选；
- 6 个（13%）必须标 ambiguous；
- 10 个（21%）无匹配，可能是伪源/暗星/混合/星表缺失，不能叫“新天体”。

所以完整缓存的潜力是“多数检测源可给候选”，但不是“多数恒星可识别”。

---

## 3. 更关键的：检测源只占真实星的一小部分

同一 Barnard 场：

- C 单期检测源：**47**
- 同区域 Gaia 星：**2,583**
- 检测/真实星：**约 1.8%**

因此：

```text
星表识别：能覆盖“我们检测到的源”的 79%
整体识别：只能覆盖“真实星”的 1.8%
```

星表匹配不能弥补**检测深度/混合/饱和度**；这正是之前单图测试的结论。

---

## 4. 官方 5 个目标是不是“多数”？

不是。它们只是**目标级、手工选择的 5 个案例**：

| 目标 | identity | 说明 |
|---|---|---|
| Barnard | known_star | Gaia 1 候选 |
| Eps Ind B | ambiguous | RUWE 4.30，多候选 |
| WISE 0855 | insufficient_data | 极暗/历元少 |
| RW Aur | ambiguous | 双源 |
| R Dra | known_star | Mira |

- 2/5 是 known；
- 2/5 是 ambiguous；
- 1/5 是 insufficient；
- 且这是**目标卡级别**，不是全场 47/215 个源批量识别；
- 官方实例只用于基准，不是“多数能力”的证明。

---

## 5. 为什么现在像“只标注案例”

1. **B 当前是 250 行 fixture**，不是 17,679 生产缓存；
2. **没有批量识别入口**：A/C 源列表只显示检测源，点某个才 `/api/identify`；
3. **Tracks D1 只检查有限 track，且 B partial 时直接 0**；
4. **C 源识别常 `insufficient_data`**，因为 B partial；
5. 星表匹配是**按检测源**，不是按全图/全星表；
6. 检测本身只覆盖亮源的一小部分。

---

## 6. 要达到“多数检测源可识别”，需要做什么

### P0

1. 用完整 17,679 Gaia 缓存替换 250 行 fixture；
2. 确认 `catalog_status=ok`（不是 partial）；
3. 对 A/C 源表做**批量匹配**，不是只点选；
4. 结果分 `single_candidate / ambiguous / no_match`，不把 no_match 写成未知。

### P1

1. 加 2MASS/WISE/SIMBAD 交叉，补 Gaia 缺失的极红星/褐矮星；
2. 批量识别限制在星表覆盖区（`catalog_status=ok`）；
3. 对 ambiguous 显示多候选，不强行给单一名称；
4. 统计识别率/误配率，而不是只看 5 个案例。

### P2

1. 提升检测深度（同波段 stack/多波段）；
2. 处理饱和/混合；
3. 明确“检测覆盖率”和“识别覆盖率”是两个指标。

---

## 7. 最终回答

| 问题 | 答案 |
|---|---|
| 当前是否多数可识别？ | **不是**；当前只标注目标卡/点击源 |
| 官方 5 案例是否代表多数？ | **不是**；是手工目标级基准 |
| 当前 B 对 47 个 C 源 | 0/47（fixture partial） |
| 完整 Gaia 缓存潜力 | 37/47 有候选（79%），31/47 单候选（66%） |
| 能否识别“多数恒星”？ | **不能**；检测只覆盖约 1.8% 真实星 |
| 能否识别“多数检测源”？ | 完整缓存下**可以接近多数**，但仍有 21% no_match、13% ambiguous |

**一句话：现在是“案例级/选中源识别”，不是“多数恒星识别”。完整 B 缓存能把它提升到“多数已检测源有候选”，但仍不是全星识别，也不能把 no_match 当新天体。**
