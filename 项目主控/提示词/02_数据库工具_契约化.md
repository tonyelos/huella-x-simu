## 任务

### T1. 新增 `/api/v1/epochs`

**规范 DTO（每个历元必须有）：**

```json
{
  "obsid": "2025W35_2A_0221_1",
  "detector": 2,
  "release": "dr1",
  "week": "2025W35_2A",
  "version": "l2b-v27-2026-231",
  "mjd": 60916.656062,
  "date_obs": "2025-08-29T15:44:43.747",
  "sep_deg": 0.229,
  "key": "dr1/level2/2025W35_2A/l2b-v27-2026-231/2/...fits",
  "slice_url": "https://irsa.ipac.caltech.edu/...?center=...&size=0.25",
  "provenance": "real",
  "frame_id": 744
}
```

规则：

- 同一 `(obsid, detector)` 只出现一次；同一 `mjd`（±0.02 d）按 `sep_deg` 最小去重。
- 排序：`mjd` 升序，再 `detector` 升序。
- `date_obs` 不得为 null：优先 DB 字段，缺失时由 `mjd` 转 UTC ISO（`datetime.fromtimestamp((mjd-40587)*86400, timezone.utc)`，保留毫秒/微秒精度即可）。
- `slice_url` 的 `size=fov`，不要固定 0.05/0.2。
- `provenance` 对目录里的真实历元固定 `real`。
- 响应外层：`schema_version`、`query`、`matched_target_id`、`coverage`、`epochs`、`count`、`generated_at`。
- `matched_target_id`：当 `ra/dec` 落在某个 target 的 0.05° 内时返回该 id，否则 null；app 可用它复用目标的 truth/coord_unc。

**目标感知（关键）：**

- `?ra=&dec=` 进来时，先判断是否落在某个 `targets` 的 0.05° 内；若命中，优先用该目标的 `target_epochs`（curated），否则用 `frames` 锥搜索。
- 这样“手动输入 Barnard 坐标”和“点 Barnard 预设”会得到同一组历元，这是 R1 的核心体验。
- 0.05° 阈值要写进文档；WISE 0855 的坐标歧义约 0.027°，必须覆盖。

**兼容：**

- 保留现有 `/api/epochs`，但内部委托到同一套规范化逻辑；加 `?format=movescope` 或直接修正旧形状。
- 不要让旧客户端（app 的 `data.py`）突然 KeyError；如果保留旧形状，明确标记 deprecated。
