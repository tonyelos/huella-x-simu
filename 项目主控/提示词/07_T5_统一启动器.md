# 07 · T5 统一启动器（Launcher / Health）

> 工作区根目录：`/Users/yiao/Documents/huellaX`；以下所有相对路径以此为准。

## 工具定义

| 项 | 定义 |
|---|---|
| **名称** | 统一启动器 / Launcher |
| **类型** | 内部工程工具（演示/开发启动） |
| **一句话** | 一条命令按顺序启动 DB、MoveScope、视图工具，做健康检查，打印三个 URL；一条命令干净停止。 |
| **Owner** | 项目主控 / 演示保障 |
| **输入** | 三个工具目录、固定端口、可选 `--offline` |
| **输出** | 运行中的三服务 + PID/日志 + `status` 报告 |
| **依赖** | bash + Python stdlib；不新增依赖 |
| **非目标** | 不做进程守护/容器编排/公网反代；不自动改端口；不杀非自己启动的进程 |
| **验收** | 一条命令 30 s 内三服务全绿；重复执行不产生孤儿；`stop` 后端口全释放；端口被占时明确报错 |

## 当前事实

- app 默认端口 8765，README 写 8790；视图 `start.sh` 扫 8790–8829，会撞 app；DB 默认 8797。
- 三套启动命令、三个终端；健康检查靠人。
- 没有 PID/日志管理；演示时无法确认“三个都起来了”。
- 没有 `git` 基线；启动器应打印 commit/tag（若存在）或 `no-git`。

## 目标（Definition of Done）

1. `start_all` 一条命令启动 DB → app → view，全部健康后打印 URL。
2. `stop_all` 只停自己启动的进程，端口全部释放。
3. `status` 显示三服务 health、PID、端口、数据快照。
4. 端口被占时明确报错（谁占的、怎么改），不自动换端口。
5. 日志集中、可追踪；重复执行不产生孤儿进程。
6. 不改三工具源码。

## 任务

### T1. 目录与命令

```text
项目主控/启动/
  start_all.sh
  stop_all.sh
  status.sh
  README.md
  logs/          # 运行时生成
  run/           # pid 文件
```

建议：

```bash
./start_all.sh                 # 默认 8790/8797/8830
./start_all.sh --offline       # 设置黑洞代理，验证离线（可选）
./status.sh
./stop_all.sh
```

要求：

- 固定端口：app 8790、DB 8797、view 8830；不要扫描。
- 启动顺序：DB → app → view。
- 每个服务启动后轮询 health（最多 15 s，200 ms 间隔）：
  - DB：`GET http://127.0.0.1:8797/api/health` → 200 且 `ok=true`；
  - app：`GET http://127.0.0.1:8790/api/health` → 200 且 `ok=true`；
  - view：`GET http://127.0.0.1:8830/` → 200（静态页无 health）。
- 失败时：打印该服务最后 50 行日志，停止已启动的服务（回滚），退出非零。
- 端口预检：启动前检查 8790/8797/8830；被占则打印进程 PID/命令，退出 1，不要杀。
- PID 文件写到 `run/*.pid`；只停这些 PID，且校验命令行包含预期脚本，避免 PID 复用误杀。
- 日志：`logs/db.log`、`logs/app.log`、`logs/view.log`；时间戳。
- `status.sh`：三服务 health、端口、PID、`app/data` 最新时间、DB `schema_version`、当前 git tag/`no-git`。
- `stop_all.sh`：先 view → app → DB，TERM，等待 5 s，仍存活再 KILL（仅自己的 PID）。

### T2. 离线模式（可选但建议）

- `--offline`：对 app 进程设置 `HTTPS_PROXY=http://127.0.0.1:9`、`HTTP_PROXY=...`、`NO_PROXY=127.0.0.1,localhost`；DB/view 不需要外网。
- 打印“离线模式：IRSA 不可达，使用本地缓存”。
- 不修改 app 代码。

### T3. 文档

`README.md` 写：

- 端口表、启动/停止/状态命令；
- 日志位置、PID 位置；
- 常见错误：端口被占、DB 未初始化、视图 404、Python 路径不对；
- 与 T1 验收工具的关系（先 start_all，再跑验收）。

## 文件所有权 / 边界

**你可以改/新建：** `项目主控/启动/` 全部。
**你不要改：** `app/`、`数据库工具/`、`视图工具/`、`项目主控/01-03` 审计结论。

## 验收命令与期望

```bash
cd /Users/yiao/Documents/huellaX/项目主控/启动

# 1) 启动
./start_all.sh
# 期望：30 s 内打印
#   DB   http://127.0.0.1:8797  ok
#   app  http://127.0.0.1:8790  ok
#   view http://127.0.0.1:8830  ok

# 2) 状态
./status.sh
# 期望：三服务 ok；端口/PID；schema；git/no-git

# 3) 重复启动
./start_all.sh
# 期望：识别已在运行，不重复起进程；或明确提示已在运行

# 4) 停止
./stop_all.sh
# 期望：三端口释放；无孤儿
lsof -nP -iTCP:8790 -iTCP:8797 -iTCP:8830 -sTCP:LISTEN || true

# 5) 端口冲突
# 先用其他进程占 8790，再 ./start_all.sh
# 期望：明确报错（谁占的），不自动换端口
```

**期望：**

- 三服务健康；view 页面 200；app `/api/health` 200；DB `/api/health` 200。
- 重复执行不产生第二个 app/DB/view。
- `stop_all` 后无监听端口；PID 文件清理。
- 端口冲突时不杀别人、不偷偷换端口。
- 日志可读，失败能定位。
