# 06 · T3 离线演示冻结器（Offline Demo Freezer）

> 工作区根目录：`/Users/yiao/Documents/huellaX`；以下所有相对路径以此为准。

## 工具定义

| 项 | 定义 |
|---|---|
| **名称** | 离线演示冻结器 / Offline Demo Freezer |
| **类型** | 内部工程工具（演示保障，不对外） |
| **一句话** | 把 5 个官方目标 + 指定自定义坐标所需的 NPZ 切片冻结成带 sha256 清单的可移植快照，断网也能复现同一结果。 |
| **Owner** | 项目主控 / 演示保障 |
| **输入** | 目标列表、坐标列表、FOV；现有 `app/data/epochcache/*.npz`；可选网络（补缺失缓存） |
| **输出** | `demo/snapshot-<date>/`（manifest.json + epochs/ + results/ + README）+ `verify` 报告 |
| **依赖** | `app/core/data.py` 的缓存/取数函数；T2 的 resolver（用于自定义坐标，可选） |
| **非目标** | 不改科学管线；不生成新历元；不替代头文件采集器；不冻结整幅 65 MB FITS |
| **验收** | 5 目标断网 5/5 与在线一致；manifest sha256 全匹配；快照可拷到另一目录直接跑；缺文件能明确报错 |

## 当前事实

- `app/data/epochcache/` 有 55 个 NPZ，覆盖 15 个 pointing 区域；Barnard/Eps/WISE/M101/场 A。
- 阻断 `urllib` 后跑完整管线，5 目标全部成功，结果与在线一致（0.3–0.6 s/目标）。
- RW Aur / R Dra 走 HYBRID（模拟），不需要网络；但它们没有真实 NPZ。
- 缓存键由 `app/core/data.py::_cache_path` 决定；T2/01 可能改缓存键（加版本、原子写），冻结器必须复用，不要自己拼路径。
- 没有 manifest、没有 sha256、没有“缺哪期”的报告；演示前无法确认“到底冻了哪些”。

## 目标（Definition of Done）

1. `freeze` 能生成一个自包含快照目录（不依赖 `app/data/epochcache` 的绝对路径）。
2. `manifest.json` 列出每个目标/坐标的每个历元、对应文件、sha256、bytes、来源 URL、版本。
3. `verify` 能重算 sha256，发现缺失/损坏/多余文件。
4. `run --offline` 能在断网环境跑完 5 目标，结果与在线一致。
5. 快照可拷到 `/tmp/demo` 或另一台机器（同 Python 环境）直接跑。
6. 不修改 app/DB/view 源码。

## 任务

### T1. 目录与 CLI

```bash
项目主控/冻结/
  freeze.py
  verify.py
  run_offline.py
  README.md
```

建议命令：

```bash
python3 freeze.py --targets all --coords "269.452077,4.693365;331.044147,-56.782844" \
  --fov 0.25 --out demo/snapshot-2026-11-14

python3 verify.py --snapshot demo/snapshot-2026-11-14

python3 run_offline.py --snapshot demo/snapshot-2026-11-14 --targets all
```

要求：

- 只允许 stdlib + numpy（读 NPZ 可用 numpy）；不引入新依赖。
- 不要求服务在跑；可直接 import `app/core`。
- `--out` 已存在时：默认拒绝覆盖；`--force` 才重建。
- 所有路径相对快照根，manifest 内不写绝对路径。

### T2. 解析要冻结的历元

- 5 个官方目标：读 `app/data/epoch_catalog.json` + `app/core/data.py::dedupe_epochs`，用 `max_real=8` 的同一抽样规则（与 `build_dataset` 一致）。
- 自定义坐标：
  - 若 T2 `epoch_source.resolve_epochs` 可用，用它；
  - 否则退化为“按坐标查 `app/data/epoch_catalog.json` 的最近目标”，并明确标记 `resolver=fallback`。
- 对每个历元计算表观位置：优先复用 `app.core.data.apparent_position(target, mjd)`；自定义坐标若无 truth，直接用输入 ra/dec。
- 计算缓存路径：**必须**复用 `app.core.data._cache_path(ep, ra, dec, size)`，不要自己拼字符串。
- 若缓存缺失：
  - 默认 `--fetch` 才联网补；不加 `--fetch` 时记录 `MISSING`，不静默生成。
  - 补数失败：记录 `FETCH_FAILED`，不伪造文件。
- 对 HYBRID/SIM 目标（RW/R Dra）：记录 `mode=hybrid`、`network_required=false`，不要求 NPZ；但仍要冻结它们的输入（目标坐标、truth、模拟种子/时间轴）以保证可复现。

### T3. 快照布局与 manifest

```text
demo/snapshot-2026-11-14/
  manifest.json
  README.md
  epochs/
    barnard/
      dr1_2025W35_2A_0221_1_D2_269.4462_4.7673_0.250.npz
      ...
  results/
    barnard.json       # 冻结时的 API 结果（若服务可用）
    epsind_b.json
  checksums.txt
```

`manifest.json` 至少包含：

```json
{
  "schema_version": "1.0",
  "generated_at": "2026-11-14T22:30:00Z",
  "app_git": "no-git-or-tag",
  "python": "3.12.14",
  "fov": 0.25,
  "targets": [
    {
      "id": "barnard",
      "ra": 269.452077,
      "dec": 4.693365,
      "mode_expected": "real",
      "epochs": [
        {"obsid": "...", "detector": 2, "release": "dr1", "week": "...",
         "version": "...", "mjd": 60916.656062, "date_obs": "...",
         "key": "...", "slice_url": "...", "file": "epochs/barnard/....npz",
         "sha256": "...", "bytes": 111313, "status": "ok"}
      ]
    }
  ],
  "coords": [
    {"ra": 269.452077, "dec": 4.693365, "fov": 0.25, "resolver": "target_match",
     "epochs": [...], "status": "ok"}
  ],
  "missing": [],
  "warnings": []
}
```

要求：

- `sha256` 对文件内容；`checksums.txt` 为 `sha256  relative/path` 格式，可用 `shasum -a 256 -c` 校验。
- `status` ∈ `ok | missing | fetch_failed | no_coverage | hybrid_no_pixels`。
- `results/*.json` 可选：若 8790 在跑，调用 `/api/analyze` 冻结结果；否则记录 `skipped`。
- 不复制 65 MB FITS；只复制 NPZ。

### T4. verify

`verify.py`：

- 读 manifest；逐个文件重算 sha256；缺失/不匹配 → 非零退出。
- 检查 manifest 内没有绝对路径、没有 `..`。
- 检查每个 target 的 `status=ok` 的历元数 ≥2（real 目标）；HYBRID 目标允许 0。
- 检查 `checksums.txt` 与 manifest 一致。
- 输出 JSON + 人读摘要。
- `--strict`：任何 `missing/fetch_failed` 都失败；默认 warning。

### T5. run_offline

`run_offline.py`：

- 用 `unittest.mock` 或 monkeypatch 把 `urllib.request.urlopen` 替换为抛错，模拟断网。
- 从快照加载 NPZ（或临时把 `app/data/epochcache` 指向快照 `epochs/`），跑 `build_dataset` + `run_pipeline`。
- 对 5 目标输出：`mode/readiness/class/μ`，与 `results/*.json` 或黄金表对比（容差同 T1）。
- 若 RW/R Dra 的 HYBRID 需要背景/PSF，确认 `app/data/backgrounds`、`psf_d2.npy` 存在；缺失则报错，不要静默。
- 退出码：0 全过；1 结果不一致；2 环境错误。

### T6. README

写清楚：

- 这个快照是什么、不是什么（不是原始 FITS，不含 EPSF）。
- 如何冻结、如何校验、如何离线跑。
- 已知限制：RW/R Dra 无真实像素；任意未覆盖坐标会 `NO_LOCAL_COVERAGE`；缓存键依赖当前 app 版本。
- 演示命令（一条）。
