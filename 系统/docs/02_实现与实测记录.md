### 2.2 周指向索引

`tools/scan_week_index.py` 对 151 个周目录（QR3 41 + DR1 110）各读一个 level2 文件的
`SPS_ELON / SPS_ELAT / DATE-OBS`，生成 `app/data/week_index.json`。
用途：把"任意坐标"先映射到"黄经接近的候选周"，避免盲取整幅 65 MB 文件。

### 2.3 目标历元发现结果

`tools/find_epochs.py` 的做法：候选周内扫描全部场号的探测器 1 头部（约 328 次/周）→
取视场中心距目标 <7.5° 的场 → 逐探测器确认（<1.9°）→ 输出切片 URL。
实测结果：

| 目标 | 原始历元 | 去重后时刻 | 覆盖周 | 时间基线 |
|---|---|---|---|---|
| Barnard's Star | 8 | 4 | 2025W35 / 2025W36 / 2026W12 | 204 天 |
| Epsilon Indi B | 20 | 10 | 2025W41 / 2025W43 / 2026W18 / 2026W40 | **361 天** |
| WISE 0855−0714 | 20 | 9 | 2025W44 / 2025W45 / 2026W18 | 183 天 |
| RW Aurigae | 2 | 1 | 2026W37 | 1 天 |
| R Draconis | 6 | 3 | 2025W24 | 1 天 |
| M101 视场 | 10 | 5 | 2025W51 / 2026W25 | 187 天 |
| 场 A（DR1） | 8 | 3 | 2025W17 / 2025W48 | 215 天 |

> 关键发现：SPHEREx 同一曝光会被多个探测器同时记录（时间戳到微秒相同）。
> 必须先按 MJD 去重，否则同一时刻会被当成多个独立历元，权重翻倍。

### 2.4 取数与缓存

- 切片 URL 由 `release + key + ?center=RA,Dec&size=deg` 拼出，`size` 单位是**度**。
- 每期 4 MB 里 97% 是 EPSF；服务端只保留 IMAGE/FLAGS/VARIANCE/ZODI + 头 + 33×33 归一化 PSF，
  缓存为 `.npz`（约 100–200 KB）。
- 打包 Python 没有系统 CA；取数时显式使用 `/opt/homebrew/etc/openssl@3/cert.pem`（存在才用），
  否则 `/etc/ssl/cert.pem`。
- IRSA 偶发 503：每个历元最多重试 3 次（退避 1.5/3 s）。实测 Eps Ind B 首轮 10 期里有 3 期 503，
  重试后 8 期成功。

## 4. 关键实现细节（踩过的坑）

1. **FITS 头不是 2880 字节**。SPHEREx 的 IMAGE 头有 9 块（25 920 字节）。按单块读取会把数据块
   当成头，解析出 10 个"空 HDU"。
2. **WCS-WAVE 是 BINTABLE，不是图像**。`TDIM3=(2,nx,ny)`，Fortran 序，读成 `(ny,nx,2)`。
3. **切片的 SIP 系数与全幅相同**，CRPIX 平移后 `u=x−CRPIX` 不变，所以直接套用即可；
   全幅 CRPIX 实测 1020.5（D2/D6），切片偏移 = 1020.5 − CRPIX_cut。
   由此可把切片像素映射回探测器坐标并插值 LVF 波长：M101 切片中心 λ=1.484 µm，场 A 为 4.683 µm。
4. **匹配滤波必须先减背景**。不减背景时整幅图的 SNR 被 DC 抬到 ~19，`find_peaks` 会报 80 个假峰。
5. **PSF 归一化差 25 倍**。EPSF 在 33×33 过采样网格上 sum=1；采样到一个像素要乘 `oversample²`，
   否则渲染出的星只有应有亮度的 4%。
6. **相对定标必须排除目标自身**。目标在动，如果混进参考星，仿射改正会把它的运动一起扣掉；
   实测会导致回收的 μ 偏低约 30%。
7. **多波段流量不可直接比较**。不同探测器（D1/D2/D4/D5/D6）的流量差 6 倍以上；
   工具在 `multi_band=True` 时关闭变光模型，只做位置模型比较。
8. **没有流量模型时也要输出位置模型对比**。最初版本把"无可用流量"写成"没有模型"，
   导致 Eps Ind B 的 BIC 面板为空；已修。
9. **周期必须有双重守卫**。R Dra 注入周期 245 天、基线 205 天（<1 个周期），
   拟合会给出 1.0 天的别名；现在要求 **基线 ≥1.3 个周期** 且 **P > 2×中位采样间隔** 才报告周期。
   8 期/205 天的采样下，R Dra 的周期显示为"—"——这是诚实的结果。
10. **物理合理性守卫**。跨历元误关联可能拟合出 40″/yr 的"自行"；超过恒星先验 30″/yr 时
    结论降级为 U，并标记 `IMPLAUSIBLE_PM`。

### 5.1 注入-回收（合成数据，已知真值）

|---|---|---|---|---|---|
| Barnard's Star | L | 8/8 | 0.98 | 13.8° | 6.5σ |
| Epsilon Indi B | L | 8/8 | 1.07 | 10.1° | 3.8σ |
| WISE 0855 | L | 8/8 | 1.14 | 1.9° | 6.1σ |
| RW Aurigae | V | 8/8 | — | — | — |
| R Draconis | V | 8/8 | — | — | — |

**平均分类正确率 100%**。注意：这里的"回收比"是相对**注入值**（在目录真值上故意加 8% 缩放和 3.5° 方向偏移），
不是相对目录值——否则就是用答案生成答案。

就绪度实验（Barnard）：2 期 → L1；4 期 → L2；8 期 → L2（基线 205 天 <0.6 yr 时不上 L3）。

### 5.2 真实数据：Epsilon Indi B（旗舰结果）

- 数据：8 期真实 SPHEREx level2 切片（D1/D2/D4/D5/D6），基线 **361 天**。
- 参考星相对定标：每期 **10–21 颗**匹配星，仿射残差 RMS **0.108–0.784 px**（快照复算口径）。
- 结果：**L 匀速直线**，μ = **4.71 ± 0.55 ″/yr**，PA = **129.6°**，位移 4.41 ± 0.98″。
- 真值（SIMBAD）：μ = 4.68 ″/yr，PA = 121.8°。**μ 偏差 0.04σ**；PA 差 7.8°，
  与 μ 的 6.6% 相对误差对应的 ~6.7° 同一量级（v1 没有单独的 PA 误差字段，不做 σ 声明）。
- 模型：M2 45% / M3 33% / M4 23% / M0 0%（ΔBIC(M0−M2)=142）。
  8 期、1 年基线仍不足以把视差（0.27″）从自行为中分离——工具如实显示 M3 与 M2 同权，
  没有硬说"测到了视差"。
- 就绪度：**L3**；质量标记 `LARGE_CENTROID_ERROR`（保守的 0.05 px 系统项）；
  多波段 caveat。

### 5.3 真实数据：Barnard's Star（饱和案例）

- 数据：4 期真实切片，基线 204 天；参考星仿射 RMS 0.12–0.17 px（定标本身很好）。
- 目标在 SPHEREx 上**饱和**：峰值 755–1766 MJy/sr，核心 NaN + BLOOM/HALO 位。
- 结果：位移约 **5.3″**（真值 5.8″；0.25° 视场 5.35″，0.2° 视场 5.29 ± 6.69″），质心误差 0.4 px。
  **μ 的口径必须分开写**：0.25° 视场 8.03 ± 9.90 ″/yr；0.2° 视场 12.24 ± 9.90 ″/yr（同一目标、不同视场/参考星集合）。
  两者都**不显著**，判为 S（无明显位移），附 `SATURATED_SOURCE` 与 `LARGE_CENTROID_ERROR`。
- 评价：这是**正确的不作为**。用单帧饱和像强行宣称 10″/yr 是不诚实的；
  工具给出了接近真值的中心值与诚实的上限。

### 5.4 真实数据：WISE 0855（坐标歧义）

- 赛道坐标与 SIMBAD MIR 坐标相差约 1.6′；本工具的目录真值传播后落在两者之间。
- 8 期真实数据里只有 1 期达到 3σ 探测；其余为强制测光，工具拒绝用噪声硬凑轨迹。
- 结果：**U 不可判定（L0）**，并提示"目标太暗或坐标偏差较大"。
- 这是数据/坐标问题，不是算法失败；注入-回收里同一目标分类正确率 8/8。

### 5.5 反例：RW Aur / R Dra

- 两目标的真实历元都只有一个时刻（RW Aur 1 个；R Dra 3 个但集中在 1 天内），
  自动模式回退到 HYBRID（真实 PSF/噪声 + 注入目标），基线 205 天。
- 结果：均判 **V 变光**，位置斜率 <1σ；振幅 0.47 / 1.49 等。
- 这正是官方埋的考点：**亮度变化不被误判为移动**。

### 5.6 运动 vs 变光的受控对照（每类 30 个随机种子）

为专门回答"会不会把变亮当成移动"，用同一套 `analyze_track` 跑了五类受控轨迹
（`tools/test_motion_vs_variability.py`，结果 `docs/motion_vs_variability.json`）：

| 类别 | 构造 | L | V | S | U | A | 误判为运动 |
|---|---|---|---|---|---|---|---|
| A 纯变星 | μ=0，振幅 2 等，P=245 d | 0 | **30** | 0 | 0 | 0 | **0%** |
| B 纯移动 | μ=10.4″/yr，恒亮 | **30** | 0 | 0 | 0 | 0 | 100%（正确） |
| C 又动又变 | μ=8″/yr，振幅 1 等 | **30** | 0 | 0 | 0 | 0 | 100%（正确） |
| D **变星+混叠** | 位置本不动，质心随亮度被邻星拉偏 | 0 | **30** | 0 | 0 | 0 | **0%** |
| E 移动+混叠 | μ=8″/yr + 混叠漂移 | 5 | 8 | 0 | 0 | 17 | 73%（保守漏检 8 例） |

关键点：

- **A 类 30/30 判 V**，μ 中位数 335 mas/yr、显著性 0.8σ——亮度变化没有变成位置趋势。
- **D 类是最危险的陷阱**：变星与邻星混叠时，质心会随亮度漂移，产生一条"假轨迹"。
  **补上 `_blend_check`（位置 = a + b·t + c·F 的偏 F 检验）之前，30 次里有 16 次误判为移动**；
  补上之后 **0 次**，并标记 `BLEND_INDUCED_WANDER`。
- **C 类 30/30 判 L**：真正的"又动又变"不会被变光掩盖。
- **E 类是已知代价**：真实运动叠加混叠时，若变光周期长于基线，`t` 与 `F` 近简并，
  8/30 被保守地降级为 V。工具不会把这种情况说成"确定移动"。

## 6. 与理论文档的偏差登记

### 13.1 后端：`cascade_layers(epoch)`

文件：`系统/app/core/pipeline.py`

纯函数，返回：

```json

  "residual_threshold": 5.0,
```

- L1：复用 `detect_sources`（6σ，`max_l1=80`，与 A/C 的 `detect_sources(max_sources=80)` 一致），按 1.2 px 去重，避免同一 PSF 多个近邻峰把 masked 计数放大。
- masked：L1 源位置，半径 2 px，`reason=already_detected`；像素用局部环带中值替换，并写入 mask。
- residual：mask 后的图用 **5.0σ** 再检测，`max_residual=80`；排除离任一 L1 中心 <2 px 的重复；`quality` 加 `RESIDUAL_CANDIDATE`；`EDGE`/`LOW_SNR` 通过 quality 标记。
- 旧版 `max_l1=300` + `residual=4.5` + `max_residual=300` 会得到 Barnard 725/484；这是把 detector 的高召回上限误当成 per-epoch 源表上限，已修正。
- `detect_sources(..., mask=...)` 新增可选 mask；默认 None，不改变现有路径。
- 没有 WCS 时 RA/Dec 为 null，不编造；空/None epoch 返回空层。

纯函数测试使用 48×48 synthetic 图像：2 个亮峰 + 1 个约 5σ 的暗峰，验证 `l1=2, masked=2, residual≥1`、parent/masked_by、2 px 排除、mask 生效。

## 14. 跨历元轨迹（Tracklet MVP，2026-11-15）

> `/tracks`：把 `/cascade` 的 L1 + residual 节点关联成 tracklet，输出 D0–D4 候选分级。
> **轨迹候选不是新天体；D5 才需要人工/后续确认。** D0–D4 不是发现声明。

### 14.1 纯函数 `tracklets`

文件：`系统/app/core/tracks.py`

输入：

```python
[
  {"epoch_id": "e0", "mjd": 60000.0, "pixel_scale_arcsec": 6.15,
   "nodes": [{"source_id": "...", "stage": "l1", "x": 10.0, "y": 10.0,
              "ra": 10.0, "dec": 20.0, "snr": 20.0, "flux": 10.0,
              "flux_err": 1.0, "quality": []}]},
  ...
]
```

关联：

- 按 mjd 排序，逐历元贪心最近邻；
- 位置门限默认 3 px，gap 1 期时放宽到 1.5×；
- 允许缺 1 期；节点不复用；
- 空历元保留在时间轴上，用于 transient/gap 判断。

模型：

| 模型 | 判据 |
|---|---|
| `stationary` | 位置线性/二次项不显著，且流量不显著变化 |
| `linear` | 直线相对常数 ΔBIC>6，速度 ≥3σ |
| `curved` | 二次项相对直线 ΔBIC>6（≥4 期） |
| `variable` | 位置 stationary，流量 χ²/dof>9 |
| `transient` | 1 期或缺失 ≥2 期 |

层级：

| 级别 | 条件 |
|---|---|
| D0 | 任一节点 quality 命中 EDGE/SATURATED/LOW_SNR/DUPLICATE/PSF_ABNORMAL |
| D1 | B 星表单候选 + catalog_status=ok；B 不可用绝不伪造 |
| D2 | 未实现（counts=0） |
| D3 | 无星表匹配 + linear/curved |
| D4 | 无星表匹配 + stationary/variable/transient |
| D5 | 人工/后续确认，out of scope |

输出字段：`track_id, level, model, n_epochs, ra, dec, mu_arcsec_yr, pa_deg, catalog, catalog_id, catalog_status, confidence, caveats, nodes, discovery_claim=false`。非移动模型 μ=0、PA=null，避免假精度。

## 17. 数据接收后自动调用：CatalogClient ingest（2026-11-15）

> app 侧客户端能力：B match 返回 `partial`/`no_cached_field` 时，按 env 显式开启

### 17.2 自动重试规则

`CatalogClient.match()` 在 normalize 后：

1. 环境变量 `CATALOG_AUTO_INGEST=1`（默认关闭）；
2. 结果 `catalog_status` 为 `partial` 或 `unavailable`；
3. reason 为 `no_cached_field` / `partial`（partial 状态本身也允许）；
4. 调 `ingest(ra, dec, radius_deg=0.25, mag_limit=20.0, include_photometry=False)`；
5. ingest 成功 → **重试 match 一次**，返回重试结果，并在结果上附：
   `auto_ingest: {attempted, ok, field_id, reason, http_status}`；
6. ingest 失败/超时 → 保留原 match 状态，附失败原因；不伪造 known/ok。

超时：

```text
MOVESCOPE_CATALOG_INGEST_TIMEOUT=60   # 默认 60s
MOVESCOPE_CATALOG_TIMEOUT=2.5         # 原 match 超时，不受影响
```

`_allow_auto=False` 仅内部用于重试，防止 ingest 后递归再次 ingest。
